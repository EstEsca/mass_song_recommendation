# 가사 형식 검증 스킬

> ⚠️ **DEPRECATED (2026-04-25~) — v2 스키마 미대응**
>
> 이 스킬은 v1 스키마 기준이라 현재 v2와 호환되지 않는다. **호출 전 다음을 v2에 맞춰 리팩토링 필요:**
>
> - `가사.본문` → `가사` (단일 문자열)
> - `가사.확보여부` → `bool(가사)` 체크로 대체
> - **F7(절구조 일치) 검증 항목 제거** — `가사.절별`·`가사.절구조` 필드는 v2에서 폐기됨
> - 검증 항목 F1~F6은 본문 내 마커(`[1절]`, `[후렴]`)에 대한 것이라 그대로 유효
>
> 자세한 마이그레이션 규칙: [docs/spec/schema.md](../../../docs/spec/schema.md) "v1.0 → v2.0 매핑 규칙" 참조.
> 리팩토링 전까지 호출 금지.

songs.json의 가사가 프로젝트의 형식 스펙을 준수하는지 검증한다.
**검증(보고)만 한다. 수정은 하지 않는다.** 수정은 `/fix-lyrics-format`의 역할.

## 형식 스펙 참조

`docs/spec/lyrics_format.md` 기준.

### 핵심 규칙

- 절 마커: `[1절]`, `[2절]`, `[후렴]` 등 대괄호 형식
- 한 줄 규칙: 한 절의 가사는 한 줄에 전부
- 절 사이는 줄바꿈(\n)으로 구분
- 오염 없음: Copyright, 코드 심볼, 깨진 영문 없어야 함

## 데이터

- 입력: `data/songs.json` (가사.확보여부가 true인 곡만 대상)
- 출력: 화면 보고만. 파일 수정 없음.

## 검증 항목

| ID | 검증 | 통과 조건 |
|----|------|---------|
| F1 | 절 마커 형식 | 본문의 모든 줄이 `[N절]` 또는 `[후렴]` 등으로 시작 |
| F2 | 절 번호 순서 | 1, 2, 3, ... 순차. 빠짐 없음 |
| F3 | 한 줄 규칙 | 각 절이 정확히 1줄 (절 내부 줄바꿈 없음) |
| F4 | 오염 없음 | Copyright, 코드 심볼, 깨진 영문/특수기호 없음 |
| F5 | 한글 비율 | 각 절의 한글 비율 ≥ 70% |
| F6 | 최소 길이 | 각 절 ≥ 10자 (미만이면 가사 불완전 의심) |
| F7 | 절구조 일치 | `가사.절구조` 필드와 `가사.절별` 키 목록이 일치 |

### F4 오염 감지 패턴

- Copyright: `Copyright`, `All rights reserved`, `Used by permission`, `Administered`
- 코드 심볼: `^[A-G][#b♯♭]?(m|sus|dim|aug|maj)?[0-9]?(/[A-G][#b]?)?$`
- 깨진 영문: 한글 비율 < 50%인 토큰이 3개 이상 연속

## 실행 흐름

### Step 1: 대상 곡 확인

`$ARGUMENTS` 파싱:
- 곡 번호: `5`, `1-10`
- `전부` → 가사 확보된 전체 곡
- `미통과` → 이전 검증에서 위반된 곡만 재검증

### Step 2: 각 곡에 F1~F7 검증 실행

songs.json에서 `가사.본문`과 `가사.절별`을 읽어서 검증.

### Step 3: 결과 보고

**요약:**
```
=== validate-lyrics-format 결과 ===
대상: 434곡
통과: 150곡 ✅
위반: 284곡 ⚠️

위반 유형별:
  F1 절 마커 형식: 200곡
  F4 오염: 43곡
  F5 한글 비율: 140곡
  F3 한 줄 규칙: 30곡
  F6 최소 길이: 15곡
  F2 절 번호 순서: 5곡
  F7 절구조 불일치: 10곡
```

**곡별 상세 (위반 곡만):**
```
[8] 고백 — F4(Copyright 혼입), F1(절 마커 없음)
[1] 가서 내 형제들에게 전하여라 — F4(깨진 영문), F5(한글 비율 낮음)
```

### Step 4: 후속 안내

> 위반 곡을 수정하려면:
> - 자동 교정: `/fix-lyrics-format {범위}`
> - 수동 수정: songs.json 직접 편집
> - 웹 기반 복구: `/repair-lyrics {번호}` (명시 요청 시)

## 원칙

- **읽기 전용**: songs.json을 절대 수정하지 않음
- **외부 호출 없음**: 순수 로컬 검증
- **모든 위반을 빠짐없이 보고**: 일부만 보여주고 생략하지 않음
