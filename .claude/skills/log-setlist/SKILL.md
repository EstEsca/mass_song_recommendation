# 선곡표 기록 스킬

선곡(어떤 주일, 어떤 카테고리에 어떤 곡을 부를 것인가)을 [`data/source/선곡표.xlsx`](../../data/source/선곡표.xlsx)에 행 단위로 누적 저장한다.

## 데이터 흐름

```
사용자 자연어 또는 recommend-hymns가 넘긴 구조화 페이로드
   {주일, 전례명, 카테고리별 [{곡번호, 곡명, 선정이유}]}
        │
        ▼
스킬이 (주일, 전례명, 카테고리, 곡번호, 곡명, 선정이유, 비고) 행 목록 구성
        │
        ▼
POST /api/setlist  (server/app.py:_append_setlist_rows)
   - 선곡표.xlsx의 '선곡' 시트에 행 append
   - xlsx 잠금 시 409 → 사용자에게 엑셀 닫고 재시도 안내
        │
        ▼
사용자에게 추가된 행 수 보고
```

## 호출 모드

### 모드 A — recommend-hymns에서 호출 (구조화 페이로드)

`/recommend-hymns` Step 7에서 사용자가 "확정"하면 이 스킬을 호출한다. 페이로드:

```json
{
  "weeks": [
    {
      "주일": "2026-05-03",
      "전례명": "부활 제5주일",
      "카테고리": {
        "입당": {"번호": 12, "곡명": "...", "선정이유": "..."},
        "봉헌": {"번호": 87, "곡명": "...", "선정이유": "..."}
      }
    }
  ]
}
```

스킬이 위 구조를 펼쳐 행 목록으로 변환한 뒤 한 번의 POST로 일괄 append.

### 모드 B — 단독 호출 (사용자 자유 입력)

사용자가 "5월 3일 부활 5주일 선곡 기록해줘 — 입당 12번, 봉헌 87번..."처럼 말하면, 스킬이 다음을 묻고 채운다:

1. **주일** (YYYY-MM-DD). 미명시 시 다가오는 주일 제안.
2. **전례명** (예: "부활 제5주일"). 미명시 시 주일 날짜로 추정 후 사용자 확인.
3. **카테고리별 곡**: 입당/봉헌/성체/파견/묵상 중 사용자가 말한 것만. 곡번호로부터 `data/songs.json` 또는 `data/songs_index.json`에서 곡명 자동 채우기 가능.
4. **선정이유** (선택). 비어있어도 OK.

확정 전 한 번 표 형태로 보여주고 사용자에게 확인 받는다:

```
| 주일       | 전례명       | 카테고리 | 곡번호 | 곡명         | 선정이유 |
|-----------|------------|---------|-------|-------------|---------|
| 2026-05-03 | 부활 제5주일 | 입당    | 12    | …           |         |
| 2026-05-03 | 부활 제5주일 | 봉헌    | 87    | …           |         |

이대로 기록할까요? (Y/N)
```

Y → POST 호출, N → 어떤 행 수정할지 묻기.

## API 호출

```bash
curl -X POST http://localhost:8000/api/setlist \
  -H "Content-Type: application/json" \
  -d '{"rows": [
    {"주일":"2026-05-03","전례명":"부활 제5주일","카테고리":"입당","곡번호":12,"곡명":"...","선정이유":"...","비고":""}
  ]}'
```

응답: `{"ok": true, "appended": N}` 또는 409(xlsx 잠금) / 400(잘못된 입력) / 500(파일 없음).

xlsx 잠금 시 메시지: "선곡표.xlsx가 엑셀에 열려있는 것 같습니다. 닫고 다시 시도해주세요."

## 곡명 자동 채우기

사용자가 곡번호만 말하면 곡명은 빈 문자열로 두지 말고 카탈로그에서 채워주는 것이 좋다.

- 빠른 경로: `data/songs_index.json` 읽어 `songs[번호].제목`.
- 느린 경로: `data/songs.json` 읽기 (가사 포함이라 무거움 — 가능하면 index 우선).

선정이유가 비어있으면 빈 문자열로 두되, recommend-hymns가 넘긴 구조에는 항상 들어 있다.

## 주의

- **별도 "확정일자" 컬럼 없음**. 행이 누적되는 것 자체가 진리.
- 같은 주일·카테고리에 여러 곡 허용 (한 카테고리에 두 곡 부르는 미사 등).
- 같은 주일·곡번호 중복도 허용 (검증 안 함). 사용자가 엑셀에서 직접 정리 가능.
- 행 삭제·수정은 사용자가 엑셀에서 직접 (스킬은 append만).

## 파라미터 미명시 시 진행 정책

argument-hint에 아무것도 없고 사용자도 즉답 없으면, 모드 B로 들어가 첫 질문(주일)부터 단계적으로 진행한다. recommend-hymns에서 호출됐다면 페이로드가 항상 완전하므로 질문 없이 바로 표 확인 → POST.
