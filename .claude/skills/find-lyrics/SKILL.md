# 성가 가사 찾기 스킬

성가집 PDF 이미지에서 가사를 판독하고, 웹 검색으로 검증/보완하여 정확한 가사를 추출합니다.

## 데이터 파일

- **PDF 페이지 이미지**: `s:/song_recommendation/pages/page_NNN.png` (536장, 150dpi)
- **곡목록**: `s:/song_recommendation/곡목록.csv` (번호, 제목, 작곡자, 비고)
- **색인**: `s:/song_recommendation/song_list_index_sample.xlsx` (전례별, 시기별, 성경구절, 비고 포함)
- **가사 출력 파일**: 사용자가 지정 (기본: `s:/song_recommendation/가사.json`)

### 주의: PDF 페이지 번호 ≠ 곡 번호
다절 곡이 여러 페이지에 걸쳐 있어서 페이지 번호가 곡 번호보다 큽니다. 곡 번호로 검색 시 해당 페이지를 찾아야 합니다.

## 원칙

- **항상 시간보다 정확도를 중시한다.** 느리더라도 정확한 결과를 우선.
- 여러 곡을 처리할 때는 **병렬 Agent를 적극 활용**하여 효율을 높인다.
- **에이전트당 최대 2곡.** 3곡 이상을 한 에이전트에 넣으면 컨텍스트 초과로 행잉 발생.
- **조기 종료**: 벅스에서 가사 전문을 확보하면 멜론/가톨릭정보 등 나머지 소스는 스킵.
- **소스당 최대 2회 WebFetch.** 검색 1회 + 상세 1회. 불필요한 반복 금지.

## 실행 흐름

### Step 1: 대상 곡 확인

사용자에게 묻습니다:

> 어떤 곡의 가사를 찾을까요?
> - 곡 번호 (예: 5, 10, 134)
> - 곡 제목 (예: 거룩하다 부활이여)
> - PDF 페이지 (예: page 5)
> - 범위 (예: 1~10, 50~100)
> - "전부" → 전체 곡 대상

`$ARGUMENTS`가 있으면 이를 먼저 파싱합니다.

### Step 2: 출력 설정 확인

> 결과를 어떤 파일에 저장할까요? (기본: 가사.json)
> 가사를 어떤 필드 구조로 저장할까요? (기본: 절별 분리 — 1절/2절/후렴 등)

기본값:
- 파일: `s:/song_recommendation/가사.json`
- 구조:
```json
{
  "번호": 5,
  "제목": "거룩하다 부활이여",
  "가톨릭성가": 134,
  "가사확보": true,
  "가사": "웹에서 신뢰성 있게 확보된 경우만 기록",
  "출처": "웹(사이트명)",
  "참조URL": ["https://..."]
}
```

**기록 정책 (중요):**
- 웹 검색으로 **신뢰성 있는 가사가 확보된 경우만** `가사` 필드에 본문을 기록
- 확보 실패 시 `가사확보: false`로 두고 `참조URL`만 기록 (사용자가 직접 확인)
- **PDF 이미지 판독 결과를 최종 가사로 기록하지 않는다** (검증 용도로만 사용)

### Step 3: 샘플 1곡 미리보기

대상 곡 중 **첫 번째 1곡**에 대해 아래 프로세스를 실행하고, 결과를 미리 보여줍니다.

#### 가사 추출 프로세스 (곡 1건)

**3-1. PDF 이미지 판독 (원본 기준)**
- 해당 곡의 PDF 페이지를 Read로 읽기
- 다절 곡(1절/2절/3절이 음표 아래 세 줄로 겹침)은 **1절만 가로로** 읽기
- 후렴이 별도 섹션에 있으면 후렴도 판독
- 판독 결과를 기록

**3-2. 웹 검색 (검증/보완) — 조기 종료 방식**

아래 소스를 우선순위 순서대로 시도하되, **가사 전문을 확보하면 즉시 다음 곡으로 이동**합니다.

**소스 목록 및 URL 패턴:**

1. **벅스** (최우선)
   - 검색: `https://music.bugs.co.kr/search/track?q={곡제목}`
   - 가사: `https://music.bugs.co.kr/track/{트랙ID}`
   - → 가사 전문 확보 시 **여기서 종료**, 나머지 소스 스킵

2. **가톨릭정보** (성가번호가 있는 경우)
   - `https://maria.catholic.or.kr/sungga/search/sungga_view.asp?ctxtIndex={성가번호}`
   - → 가사 전문 확보 시 **여기서 종료**

3. **멜론**
   - 검색: `https://www.melon.com/search/song/index.htm?q={곡제목}`
   - 가사: `https://www.melon.com/song/detail.htm?songId={ID}`
   - → 가사 전문 확보 시 **여기서 종료**

4. **일반 웹 검색** (이전 소스 모두 실패 시)
   - WebSearch: `"{곡제목}" 성가 가사 전문 1절 2절`

5. **가사집** (WebSearch 실패 시)
   - `https://gasazip.com/search.html?search_word={곡제목}`

**실행 규칙:**
- 소스당 WebFetch **최대 2회** (검색 1회 + 상세 1회)
- 가사 전문 확보 즉시 → 다음 소스 스킵 (조기 종료)
- 모든 소스 실패 → PDF 판독 결과에 자연어 보정 적용

**3-3. 유사성 비교 및 기록 원칙**
- PDF는 **원곡 식별과 검증 용도**로만 사용. 기록 대상이 아님.
- PDF 1절 판독과 웹 결과의 핵심 키워드가 어느 정도 일치하면 → **같은 곡임을 확인**한 것으로 간주, 웹 결과의 가사를 기록
- 웹 결과가 없거나 거부된 경우 → **가사 필드는 비워두고** 참조 URL만 기록
- PDF 판독 결과를 최종 가사로 기록하지 않는다

**3-3b. 웹 소스 접근 시 주의**
- WebFetch 호출 시 내부 AI 모델이 저작권 우려로 가사 전문 반환을 거부할 수 있음
- 거부당하면 **반복 시도 금지** (같은 응답 반복). 다음 소스로 즉시 이동
- 반복 시도는 행잉 유발. 한 소스당 **최대 1회 재시도**까지만

**3-3a. 자연어 보정 (웹 미발견 시)**
PDF 판독 결과가 부자연스러운 경우, 문맥과 음절 구조를 고려하여 가장 자연스러운 한국어로 보정합니다.
- 예: "우리기만든" → "우리가 만든", "아이가에" → "아기야에게" 등
- 성경 표현, 전례 용어, 가톨릭 관용구를 우선 고려
- 보정한 부분은 원문과 함께 표기하여 사용자가 판단 가능하도록

**3-4. 신뢰도 판정**
- **높음**: 웹에서 전체 가사 확보 + PDF 1절과 일치
- **중상**: 웹에서 부분 가사 확보 + PDF 보완
- **중**: PDF 판독만, 대부분 판독 가능
- **낮음**: 다절 겹침 등으로 판독 불확실

### Step 4: 사용자 확인

> 이 결과대로 나머지 곡도 진행할까요?

### Step 5: 본 작업 실행

사용자 승인 후 병렬 Agent로 실행.
- **에이전트당 최대 2곡** (행잉 방지)
- Agent 프롬프트에 소스 URL 패턴과 조기 종료 규칙을 반드시 포함

### Step 6: 결과 보고

## 다절 곡 판독 팁

악보에서 1절/2절/3절이 음표 아래 세 줄로 겹쳐 있는 경우:
- **맨 윗줄 = 1절**, 둘째 줄 = 2절, 셋째 줄 = 3절
- 1절만 가로로 읽고, 나머지 절은 웹에서 보완
- 필요 시 이미지를 300dpi로 재추출하거나, 줄별로 크롭하여 분리 판독

## 에이전트 위임 시 프롬프트 템플릿

```
{곡번호}번 "{곡제목}" 가사를 추출합니다.

Step 1: PDF 판독 — s:/song_recommendation/pages/page_0NN.png 에서 해당 곡 찾아 1절 가로 판독
Step 2: 웹 검색 (조기 종료 방식)
  1) 벅스: WebFetch `https://music.bugs.co.kr/search/track?q={곡제목}` → 트랙ID → `https://music.bugs.co.kr/track/{ID}` 가사 확보 시 종료
  2) 가톨릭정보: WebFetch `https://maria.catholic.or.kr/sungga/search/sungga_view.asp?ctxtIndex={번호}` 확보 시 종료
  3) 멜론: WebFetch `https://www.melon.com/search/song/index.htm?q={곡제목}` → songId → 상세페이지 확보 시 종료
  4) WebSearch: "{곡제목}" 성가 가사 전문
Step 3: PDF vs 웹 비교 → 채택. 웹 미발견 시 자연어 보정.

출력: 번호, 제목, 절 구조+가사, 출처, 신뢰도. 간결하게.
소스당 WebFetch 최대 2회. 가사 확보 즉시 다음 소스 스킵.
```

## 주의사항

- 곡 제목과 번호는 반드시 곡목록.csv 또는 song_list_index_sample.xlsx의 실제 데이터에서 확인
- 가톨릭성가 번호가 있는 곡(비고란에 "가톨릭성가" 표기)은 웹 검색 확률이 높음
- 존재하지 않는 가사를 만들어내지 말 것
- 출력 파일이 이미 있으면 기존 데이터를 유지하고 추가/업데이트
