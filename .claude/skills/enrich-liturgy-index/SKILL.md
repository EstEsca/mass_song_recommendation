# 색인 보강 스킬

> ⚠️ **DEPRECATED (2026-04-25~) — v2 스키마 미대응 + 후속 스킬로 대체 예정**
>
> 이 스킬은 v1 색인 필드명을 사용하며, songs.json을 직접 Edit한다. v2에서는 두 가지 모두 부적합:
>
> 1. **v1 → v2 색인 필드명 변경**:
>    - `색인.성월별` → `색인.성월` (값 형식: `"5월 성모 성월"` → `"5월"`)
>    - `색인.대축일별` → `색인.대축일` (공백 제거: `"성령 강림 대축일"` → `"성령강림대축일"`)
>    - `색인.전례시기` → `색인.시기`
>    - 모든 v2 색인 카테고리는 **배열**(단일값도 `["5월"]` 형식)
>
> 2. **편집 대상 변경**: v2에서 SSoT는 `data/source/곡정보.xlsx`. songs.json은 빌드 산출물이므로
>    이 스킬이 Edit으로 songs.json을 수정해도 다음 `rebuild` 시 덮어쓰여진다.
>    색인 변경은 **xlsx의 `색인` 시트(tall 형식)**에 직접 추가해야 한다.
>
> 3. **후속 대체 스킬**: 같은 목적의 작업(태그 추가)은 Stage F에서 `/add-tag` 스킬로 재구현 예정.
>    `/add-tag`는 자연어로 "N번 곡에 태그 X 추가"를 받아 xlsx의 색인 시트에 직접 append한다.
>
> 따라서 이 스킬은 **호출 금지**. 색인 보강이 필요하면:
> - 즉시: 엑셀에서 `data/source/곡정보.xlsx`의 `색인` 시트 직접 편집 → `python scripts/rebuild.py`
> - Stage F 이후: `/add-tag` 스킬 사용
>
> 자세한 마이그레이션 규칙: [docs/spec/schema.md](../../../docs/spec/schema.md) "v1.0 → v2.0 매핑 규칙" 참조.

`data/songs.json`의 `색인.성월별`, `색인.대축일별`, `색인.전례시기` 필드는 현재 커버리지가 낮다. 이 스킬은 **한 주제씩** 후보 곡을 모아 제시하고, 사용자 승인 후에만 색인을 기록한다.

## 정책

- **자동 일괄 채움 금지**: [feedback_no_auto_field_fill](C:/Users/jsuhgraphic/.claude/projects/s--song-recommendation/memory/feedback_no_auto_field_fill.md) 원칙에 따라 사용자 확인 없는 저장은 하지 않는다
- **한 번에 한 주제**: "성모" 한 번, "성심" 한 번처럼 주제 단위로 실행
- **근거 제시 필수**: 제목·가사·작곡자·기존 비고 중 어떤 근거로 이 곡을 후보에 올렸는지 명시

## 우선 보강 주제 (8개)

1. **성모** — `색인.성월별 = "5월 성모 성월"`, `색인.대축일별 ∈ {성모 승천, 무염시태, 천주의 성모}`
2. **성심** — `색인.성월별 = "6월 예수 성심 성월"`, `색인.대축일별 = "예수 성심 대축일"`
3. **위령** — `색인.성월별 = "11월 위령 성월"`, `색인.대축일별 = "위령의 날"`
4. **성체성혈** — `색인.대축일별 = "그리스도의 성체 성혈 대축일"`
5. **그리스도왕** — `색인.대축일별 = "그리스도 왕 대축일"`
6. **대림** — `색인.전례시기 = "대림"`
7. **사순** — `색인.전례시기 = "사순"`
8. **부활** — `색인.전례시기 = "부활"`

## 실행 흐름

### Step 1: 주제 확정

`$ARGUMENTS`로 주제를 받고, 위 8개 중 어디에 매핑되는지 사용자에게 확인:

> "성모" 주제로 색인 보강을 시작합니다.
> 대상 필드: `색인.성월별` = "5월 성모 성월" 또는 `색인.대축일별` (승천/무염시태/천주의 성모 중 택일)
> 맞나요?

### Step 2: 후보 곡 수집

`data/songs.json`에서 다음을 검색해 후보 풀을 만든다.

**검색 소스 (우선순위 순):**
1. `제목`에 주제 키워드 포함 (예: "성모", "마리아", "어머니")
2. `가사.본문`에 주제 키워드 포함
3. `색인.비고`에 관련 메모
4. `작곡자`가 해당 주제 전문 (선택적)
5. 기존 `색인.대축일별`/`색인.성월별`에 부분 일치하는 값 이미 있는 곡

주제별 키워드 힌트는 `.claude/skills/recommend-hymns/liturgical_calendar.md`의 "색인 매칭 키워드" 열 참조.

**Grep 예시 (성모 주제):**
```
Grep pattern="성모|마리아|어머니" path="data/songs.json"
```

### Step 3: 후보 목록 제시

표로 정리해 사용자에게 보여준다:

```
## 📋 [주제] 색인 보강 후보 (N곡)

| 번호 | 제목 | 기존 색인 | 근거 | 제안 값 |
|------|------|----------|------|---------|
| 12 | 성모님 노래 | 성월별: null | 제목에 "성모" | 성월별: "5월 성모 성월" |
| 87 | 어머니의 사랑 | 대축일별: null | 가사 "어머니 마리아" | 성월별: "5월 성모 성월" |
| ... |
```

**근거 열에는 반드시 실제 문자열 증거를 인용한다.** "추측", "관련 있음"처럼 모호한 표현 금지.

### Step 4: 사용자 승인

> 위 N곡 중 실제로 색인을 기록할 곡을 알려주세요.
> - 전부 승인 / 일부만 승인 / 개별 수정 가능
> - 제안 값을 다른 값으로 바꾸고 싶으면 말씀해주세요

사용자가 특정 곡을 제외하거나 값을 수정하면 그대로 반영. 모호한 곡은 **보류** 목록으로 빼고 기록하지 않는다.

### Step 5: songs.json 갱신

승인된 곡만 `data/songs.json`의 해당 필드에 Edit로 기록한다.

- 기존 값이 `null`이면 새 값으로 채움
- 기존 값이 이미 있고 다른 주제이면 **덮어쓰지 말고 사용자에게 충돌 보고**
- 한 곡이 여러 주제에 해당하면 각 필드에 맞는 값 입력 (예: 성모 승천 대축일 곡은 `대축일별`에 "성모 승천 대축일", `성월별`은 그대로 유지 또는 "5월 성모 성월")

### Step 6: 완료 보고

```
## ✅ 색인 보강 완료

- 주제: [주제]
- 갱신된 곡: N곡 (번호 목록)
- 보류된 곡: M곡 (번호: 사유)
- data/songs.json 변경 라인: K줄
```

## 주의사항

- **Edit 전 반드시 Read로 해당 곡 블록을 확인**한다 (스키마 v1.0 준수)
- 색인 값은 [schema.md](s:/song_recommendation/docs/spec/schema.md)에 명시된 문자열 패턴을 따른다 — 새로운 값 형식은 사용자에게 확인 후 사용
- 다른 필드(가사, 신뢰도 등)는 절대 건드리지 않음
- 한 실행당 한 주제만 처리 — 여러 주제를 섞지 말 것
