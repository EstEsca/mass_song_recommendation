# 성가 가사 복구 스킬

> ⚠️ **DEPRECATED (2026-04-25~) — v2 스키마 미대응**
>
> 이 스킬은 v1 스키마(및 옛 `inbox/가사.json` 입력 모델) 기준이라 현재 v2와 호환되지 않는다.
> **호출 전 다음을 v2에 맞춰 리팩토링 필요:**
>
> - 입력 경로: `inbox/가사.json` → `data/songs.json` (이제 모든 가사가 SSoT에 통합)
> - `가사.본문`·`가사_원본` → 단일 `가사` 필드. 원본 보존이 필요하면 `_log.jsonl` 또는 git 히스토리 활용
> - `신뢰도.*` (점수·등급·세부지표·실패원인) → 모두 폐기됨. 신뢰도 산출 로직 자체 제거 또는 별도 메타 파일로
> - `가사확보: false` 체크 → `not s["가사"]`
>
> 또한 v2에서 SSoT는 `data/source/곡정보.xlsx`이므로 결과를 songs.json에 직접 쓰지 말고
> xlsx의 `가사` 시트에 반영하거나, 임시로 songs.json을 갱신하더라도 다음 빌드에 덮어쓰여진다는 점을 인지해야 함.
>
> 자세한 마이그레이션 규칙: [docs/spec/schema.md](../../../docs/spec/schema.md) "v1.0 → v2.0 매핑 규칙" 참조.
> 리팩토링 전까지 호출 금지.

OCR로 추출된 가사 텍스트의 어색하거나 불확실한 부분을, 웹 검색 스니펫을 참고하여 국부적으로 복구합니다.

## 원칙

- **웹 검색 결과를 원문(OCR)보다 신뢰한다.** OCR은 오류가 있을 수 있으므로.
- 가사 전문을 외부에서 가져오지 않는다. **검색 스니펫으로 OCR의 일부 단어만 수정.**
- 수정 전/후 **신뢰도를 모두 기록**한다.
- 시간보다 정확도를 중시한다.

## 입력

가사 텍스트만 받습니다 (메타데이터 불필요). 예:

```
/repair-lyrics 13
→ 13번 곡 "광야에서의 유혹"의 OCR 가사를 복구
```

또는:

```
/repair-lyrics 전부
→ 신뢰도가 '중' 이하인 모든 곡을 대상으로 복구
```

`$ARGUMENTS`로 대상을 파싱합니다.

## 데이터 파일

- **가사 파일**: `inbox/가사.json` (find-lyrics 출력물)
- **크롤링 데이터**: `scripts/crawler/data/maria_sungga.jsonl`
- **곡목록**: `data/raw/곡목록.csv`

## 실행 흐름

### Step 1: 대상 곡 식별

`가사.json`에서 대상 곡의 가사를 읽어옵니다.
- 특정 곡 번호 지정 시 → 해당 곡만
- "전부" → `가사확보: false`이거나 별도 신뢰도 필드가 '중' 이하인 곡 전체

### Step 2: 어색한 구간 식별

각 곡의 가사 텍스트를 분석하여 어색한 부분을 찾습니다:

**휴리스틱:**
- 한국어로 부자연스러운 음절 조합 (예: "우리기만든", "아이가에")
- 의미가 통하지 않는 구절
- 단어 중간 끊김 (예: "축 복" → "축복")
- 흔치 않은 조사/어미 결합
- `[?]` 또는 `(?)` 마킹된 부분

**LLM 평가:**
각 줄에 대해 "이 가사가 자연스러운 한국어인가? 어색한 부분이 있으면 표시해라"고 판단.

결과: 어색한 구간 목록 (위치 + 원문)

### Step 3: 컨텍스트 검색 쿼리 생성

어색한 구간마다:
- 양옆의 **확실한 단어 2~5개**를 추출
- 검색 쿼리 구성: `"{확실한앞단어}" "{확실한뒷단어}" 가사`

예:
```
원문: "사랑없는 ??? 아무 힘 없나이다"
쿼리: "사랑없는" "아무 힘" 가사
```

### Step 4: 웹 검색 + 스니펫 수집

검색 방법 (조기 종료):
1. **WebSearch**: `"{앞단어}" "{뒷단어}" 성가 가사` → 결과 스니펫 확인
2. 스니펫에서 결손 부분에 해당하는 단어 추출
3. **같은 단어가 2개 이상의 소스에서 확인되면** → 높은 신뢰도로 채택
4. 1개 소스만이면 → 중간 신뢰도로 채택 + 마킹

**실행 규칙:**
- 어색한 구간당 WebSearch 최대 2회
- 검색 결과 스니펫만 사용 (페이지 전체 fetch 금지)
- 한 곡 전체에 WebSearch 최대 6회

### Step 5: 복구 적용

**적용 기준 (웹 결과 우선):**
- 웹 스니펫과 OCR이 다른 경우 → **웹 스니펫을 채택**
- 웹에서 확인 안 되는 경우 → OCR 원문 유지 + `[미확인]` 마킹
- 웹 스니펫이 서로 상충하는 경우 → 다수결 채택 + `[교차검증필요]` 마킹

### Step 6: 신뢰도 산출

**수정 후 신뢰도 산출 기준:**
- **높음**: 모든 어색한 구간이 2개 이상 소스로 교차 확인됨
- **중상**: 대부분 확인됨, 일부 단일 소스
- **중**: 일부만 확인됨, 나머지 OCR 원형 유지
- **낮음**: 대부분 미확인, OCR 원형에 가까움

### Step 7: 결과 저장 + 보고

가사 파일에 다음 필드를 추가/갱신합니다:

```json
{
  "번호": 13,
  "가사_원본": "OCR 원문 (수정 전)",
  "가사": "복구된 가사 (수정 후)",
  "신뢰도_원본": "낮음",
  "신뢰도_수정": "중상",
  "복구로그": [
    {"위치": "1절 3번째 줄", "원문": "???", "수정": "지식은", "근거": "WebSearch 스니펫 2건 일치"}
  ]
}
```

보고 형식:
```
=== 가사 복구 완료 ===
곡: [번호] [제목]
수정 건수: N건
신뢰도: 낮음 → 중상
주요 수정:
  - "사랑 같은지식" → "사랑없는 지식은" (WebSearch 2건 확인)
  - "꿈에 아이들 어 담긴" → "나를 통해 아이들이 당신을" (WebSearch 3건 확인)
```

## 에이전트 위임 시 프롬프트 템플릿

```
{곡번호}번 "{곡제목}" 가사를 복구합니다.

원문(OCR): {가사텍스트}

Step 1: 어색한 구간을 식별하세요.
Step 2: 각 어색한 구간의 앞뒤 확실한 단어로 WebSearch 쿼리를 만드세요.
Step 3: 검색 결과 스니펫에서 결손 단어를 추출하세요.
Step 4: 웹 결과를 OCR보다 신뢰하여 수정하세요.
Step 5: 수정 전/후 가사, 신뢰도, 복구 로그를 출력하세요.

곡당 WebSearch 최대 6회. 스니펫만 사용.
```

## 주의사항

- 가사 전문을 외부에서 복사해오는 것이 아님. **OCR 결과의 국부적 수정**만 수행.
- 존재하지 않는 가사를 만들어내지 말 것.
- 수정 전 원본은 반드시 `가사_원본` 필드에 보존.
- 복구 로그는 사용자가 수정 내역을 검토할 수 있도록 상세히 기록.
