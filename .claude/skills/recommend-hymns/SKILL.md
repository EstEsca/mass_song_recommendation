# 성가 추천 스킬 (v2)

당신은 가톨릭 청소년/청년 성가대의 선곡을 돕는 전문 어시스턴트입니다.

## 데이터 파일 (v2)

- **운영 데이터(파생)**: `s:/song_recommendation/data/songs.json` — v2 스키마. 가사·색인 8카테고리 통합
- **경량 색인(파생)**: `s:/song_recommendation/data/songs_index.json` — 가사 제외, 1차 후보 필터용
- **편집 SSoT**: `s:/song_recommendation/data/source/곡정보.xlsx` — 사람 편집은 여기서만
- **선곡 기록**: `s:/song_recommendation/data/선곡기록.csv` (확정된 선곡 누적; 없으면 중복 회피 생략)
- **전례력 규칙**: `.claude/skills/recommend-hymns/liturgical_calendar.md`
- **vocab**: [docs/spec/vocab.md](../../../docs/spec/vocab.md) (시기 5종 / 성월 12종 / 역할 / 느낌 8종)

이 스킬은 **읽기만** 한다. 수정이 필요하면 사용자에게 안내(엑셀 직접 / `/add-tag` / `/label-lyrics`).

### 곡 범위
- **일반 선곡 대상**: 1~360번, 448~495번
- **미사통상문(361~447번)**: 일반 선곡 대상이 아님. 별도 요청 시에만 추천

## 두 가지 실행 모드

### 모드 A — Classic (기본)
LLM이 곡 메타·가사를 직접 검토해 선곡. 토큰 비용 높음(~30K 토큰/주). 색인이 빈약해도 동작.

### 모드 B — Funnel (experimental)
Python 스크립트가 1차 후보를 필터링하고, LLM은 후보 표만 보고 최종 선곡. 토큰 ~75% 절감. 색인이 풍부할수록 정확도 상승.

> **모드 선택 프롬프트** (Step 1.5)
> 실험적 Python 후보 필터를 사용할까요?
> - 예 (모드 B) — 빠름·토큰 절감, 색인 의존도 높음
> - 아니오 (모드 A, 기본) — 안정적·전통적

## 실행 흐름

### Step 1: 기본 설정 확인

**1-1. 기간**
> 몇 주치 성가를 추천할까요? (기본: 한 달 = 다가오는 4~5주일)

**1-2. 카테고리**
> 기본 카테고리는 **봉헌, 성체, 파견, 묵상**입니다.
> 추가하거나 빼고 싶은 카테고리가 있나요?

**1-3. 중복 허용**
> 최근 선곡과의 중복을 어느 정도 허용할까요?
> - **많이**: 2주 이내만 회피
> - **보통**: 4주 이내 회피 (기본)
> - **적게**: 8주 이내 회피

**1-4. 전례 컨텍스트 오버라이드**
> 성모성월·성심 대축일 같은 **특별 주제를 강조**할까요?

**1-5. (모드 B 선택 시) 강조 태그**
> 이번 추천에서 강조할 태그가 있나요? (예: 성령·위로·회개)
> 입력된 태그는 후보 점수에 +3씩 가중됩니다.

### Step 2: 전례 말씀 및 컨텍스트 수집

각 주일에 대해 (변동 없음):

**2-1. cbck.or.kr에서 전례 말씀**
WebFetch로 `https://missa.cbck.or.kr/DailyMissa/YYYYMMDD`:
- 전례명 (예: 부활 제3주일)
- 1독서·2독서·복음 구절 + 핵심 내용

**2-2. 전례 컨텍스트 (내부 계산)**
[liturgical_calendar.md](liturgical_calendar.md)의 규칙 적용. 산출:
- (성월, 대축일, 전례시기) 튜플
- 부활일 계산 등 필요한 경우 `python3 -c "..."`로 짧게

**2-3. (모드 B 선택 시) 핵심어 추출**
복음/독서 본문에서 5~7개의 핵심어 추출. LLM이 직접 (정확). Python 라이브러리 의존 회피. 추출된 키워드는 저장하지 않고 런타임만 사용.

### Step 3: 선곡 기록 확인

`data/선곡기록.csv`가 있으면 읽어서 최근 선곡 현황 파악.
- 많이: 2주 / 보통: 4주 / 적게: 8주

(없으면 skip — 모든 곡 후보로 간주)

### Step 4: 후보 필터링 + 선곡

#### 모드 A (Classic)

`data/songs.json`을 로드하고 각 주일 × 각 카테고리에 대해 LLM이 직접 판정. **선곡 우선순위:**

1. **대축일 레퍼토리 일치** — `색인.대축일`이 해당 대축일과 일치
2. **성경 매칭** — `색인.성경`이 주일 독서/복음과 정규화 키 일치
3. **전례시기 정서 적합성** — `색인.시기` 일치 (vocab: 대림·성탄·사순·부활·연중)
4. **성월 주제 보너스** — `색인.성월` 일치
5. **역할 적합성** — `색인.역할`이 카테고리 포함 (봉헌·성체 등)
6. **요약·키워드·느낌** — 신학 메시지·분위기 매칭
7. **곡모음집** — `색인.곡모음집`(가톨릭성가 등)을 참고 메타로 활용
8. **중복 회피 + 다양성** — 최근 선곡 회피 + 작곡자/주제 균형

#### 모드 B (Funnel)

각 주일에 대해:

```bash
# Stage 1: 후보 필터 (LLM 미호출)
echo '<JSON 컨텍스트>' | python scripts/filter_candidates.py > cand.json

# Stage 2: Wide TSV 직렬화
python scripts/serialize_candidates.py --input cand.json --output cand.tsv
```

JSON 컨텍스트 형식:
```jsonc
{
  "date": "2026-04-26",
  "season": "부활",
  "feast": null,
  "month": 5,
  "readings": {
    "gospel": "요한10:27-30",
    "1st": "사도13:14,43-52",
    "2nd": "묵시7:9,14-17",
    "keywords": ["목자", "양", "영원한생명", "부활"]
  },
  "categories": ["봉헌", "성체", "파견", "묵상"],
  "exclude_recent_days": 30,
  "top_n": 8,
  "boost_tags": []
}
```

- **Hard filter**: 시기·대축일 충돌 / 최근 중복 / (이미 적용된 곡)
- **Soft scoring**: 성경(+10/7/4/1) · 시기(+3) · 대축일(+8) · 성월(+3) · 키워드(+2n) · 요약 어휘(+1n cap 3) · 역할(+2) · boost_tags(+3n)
- **Diversity**: 작곡자(-3) / 키워드 3개 이상 겹침(-2)

산출된 `cand.tsv`(Wide TSV)를 LLM에 그대로 보여주고 카테고리별 최종 1곡 선택. 점수·근거가 이미 계산되어 있으므로 LLM은 **"여러 동점 후보 중 어느 게 가장 적합한가"**를 판정.

### Step 5: 결과 출력

주일별로 표 형태로:

```
## 📅 2026-04-26 - 부활 제4주일 (선한 목자 주일)
전례 컨텍스트: 성월=5월(성모) · 시기=부활 · 대축일 없음
복음: 요한 10,27-30 — 내 양은 내 목소리를 알아듣는다

| 카테고리 | 번호 | 곡명 | 선정 이유 |
|---------|------|------|----------|
| 봉헌 | 52 | 나는 착한 목자다 | 복음 요한 10장 직접 매칭 (점수 4) |
| 성체 | 211 | 여인아 왜 울고 있느냐 | 부활 시기 + 요한 매칭 (점수 4) |
| 파견 | 49 | 나는 세상의 빛입니다 | 색인.역할=파견 + 요한 매칭 |
| 묵상 | 5 | 거룩하다 부활이여 | 부활 시기 정서 |
```

**선정 이유는 반드시 구체적으로**:
- "성경 매칭" — 어떤 구절(`요한10:27-30`)
- "시기/대축일/성월 매칭" — 어떤 축
- "강조태그=성령" — boost_tags 매치 (모드 B)
- "요약·키워드 일치" — 어떤 어휘
- "최근 N주간 사용 안 함" — 다양성

### Step 6: 사용자 피드백 수렴

수정 요청 처리:
- 곡 교체: 다른 후보로 (점수 다음 순위)
- 분위기 조정: "좀 더 밝은 분위기로" → 모드 B면 boost_tags 추가, 모드 A면 색인.느낌 우선
- 곡 직접 지정: 사용자가 곡 번호 명시 시 그대로 반영

### Step 7: 확정 및 기록

승인 시 `data/선곡기록.csv`에 누적:

```
날짜,전례명,카테고리,번호,곡명,선정이유
2026-04-26,부활 제4주일,봉헌,52,나는 착한 목자다,요한 10장 직접 매칭
```

파일이 없으면 헤더 포함 신규 생성.

## 토큰 예산

| 모드 | 곡당 데이터 로드 | LLM 판정 | 주당 합계 |
|---|---|---|---|
| A (Classic) | songs.json 전체 ~30K | 매칭 판정 ~8K | **~39K** |
| B (Funnel) | 후보 ~30곡 TSV ~3.7K | 최종 판정 ~2K | **~8~10K** |

모드 B는 색인 라벨링이 충분할수록 정확도가 올라간다. 색인 빈약하면 모드 A가 안전.

## 추가 인자 처리

`$ARGUMENTS`:
- 숫자 → 기간(주 수)
- "다음주" → 1주
- "대림시기", "사순 3주", "성모성월" → 해당 컨텍스트 강조

## 주의사항

- **곡 제목·번호는 반드시 실제 데이터에서** (`data/songs.json` / `songs_index.json`). 존재하지 않는 번호 만들지 말 것
- **외부 호출**: cbck.or.kr WebFetch만. 결과는 메모리에서만 사용 (캐시 안 함; C-07로 보류)
- **색인 자동 보완 금지**: 빈 색인을 마주쳐도 자동으로 채우지 않음. 채우려면 `/label-lyrics` 또는 `/add-tag` 안내
- **읽기 전용**: songs.json/songs_index.json/곡정보.xlsx 모두 수정하지 않음
