# 로컬 가사 데이터 조회 스킬

로컬에 보유 중인 가사 데이터를 확인하고 반환한다.
**외부 호출 완전 금지. PDF 추출도 하지 않음. 순수 데이터 조회만.**

## 데이터 소스 (우선순위)

1. `data/songs.json` — 중앙 운영 데이터 (1차)
2. `scripts/crawler/data/maria_sungga.jsonl` — 크롤링 원본 (songs.json 미반영 시 보조)

## 실행 흐름

### Step 1: 대상 곡 확인

`$ARGUMENTS` 파싱:
- 곡 번호: `5`, `1-10`, `1,5,7`
- 제목: `"고요한 밤"`
- `전부` → 495곡 전체
- `미확보` → 가사 없는 곡만
- `확보` → 가사 있는 곡만

### Step 2: songs.json 조회

해당 곡의 `가사` 필드를 읽어서 반환:
- `확보여부: true` → 본문/절별/절구조/출처 반환
- `확보여부: false` → "미확보" 보고 + 출처 후보 안내

### Step 3: 보조 소스 교차 확인 (선택)

songs.json에 없지만 maria JSONL에 있을 수 있는 경우:
- 제목 매칭으로 maria 데이터 탐색
- 발견 시 "songs.json에 미반영된 maria 데이터 있음" 안내
- **자동 반영하지 않음** — 사용자에게 알리기만

### Step 4: 결과 보고

```
=== 가사 데이터 조회 결과 ===
[5] 거룩하다 부활이여 — 확보 (출처: maria, 219자)
[8] 고백 — 미확보
[11] 공동체송 — 확보 (출처: PDF추출(v3), 148자)
...
확보: N곡 / 미확보: M곡
```

미확보 곡에 대해:
> 가사를 추가 확보하려면:
> - PDF에서 추출: `/extract-sheet-lyrics {번호}`
> - 웹에서 크롤링: `/crawl-lyrics {번호}`

## 원칙

- **외부 호출 완전 금지** (WebFetch, WebSearch, 크롤러 실행 모두 불가)
- **PDF 읽기도 하지 않음** (그건 extract-sheet-lyrics의 역할)
- **데이터 수정 없음** — 읽기 전용 조회만 수행
- songs.json이 없으면 오류 반환 ("data/songs.json이 단일 진리 저장소 — 최근 스냅샷 복구 필요")
