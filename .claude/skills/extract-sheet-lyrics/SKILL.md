# 악보 PDF 가사 추출 스킬

> ⚠️ **DEPRECATED (2026-04-25~) — v2 스키마 미대응**
>
> 이 스킬은 v1 스키마 기준의 jsonl 출력 포맷(`{"절별": {...}}`)을 사용한다.
> 현재 v2에서는 `절별` dict가 폐기되고 `가사`는 단일 문자열이다. **호출 전 다음을 v2에 맞춰 리팩토링 필요:**
>
> - jsonl 출력 포맷: `{"번호": N, "절별": {"1절": "...", "2절": "..."}}`
>   → `{"번호": N, "가사": "[1절] ...\n[2절] ..."}` (단일 문자열, 마커 인라인)
> - 신뢰도(높음/중/낮음) 자동 부여 로직 → 폐기됨. 결과의 정확성은 사후 사용자 검토에 의존
> - PDF 추출 결과를 songs.json에 직접 병합하던 흐름 → SSoT가 xlsx로 바뀌었으므로
>   결과를 `data/source/곡정보.xlsx`의 `가사` 시트에 반영해야 함 (또는 별도 임시 jsonl로만 보관)
>
> 현재 95% 이상의 곡 가사가 이미 확보된 상태이므로 즉각 호출이 필요한 경우는 드물다.
>
> 자세한 마이그레이션 규칙: [docs/spec/schema.md](../../../docs/spec/schema.md) "v1.0 → v2.0 매핑 규칙" 참조.
> 리팩토링 전까지 호출 금지.

악보가 텍스트 레이어를 포함한 PDF(OCR된 이미지가 아닌 디지털 PDF)라면, OCR 없이 **위치 정보**로 가사를 정확히 추출할 수 있다.

## 원리

PyMuPDF(`fitz`)로 각 글자의 `(x, y)` 좌표를 얻은 뒤:

1. **Y 좌표 클러스터링** — 같은 가로줄에 있는 글자들을 묶는다 (간격 ≤ 7pt)
2. **스태프 시스템 구분** — 오선악보 덩어리 간 간격 (≤ 35pt) 으로 큰 그룹 만들기
3. **가사 밴드 필터** — 한글 포함 + 폰트 크기 정상 + 항목 수 ≥ 3
4. **절별 분리** — 한 스태프 내에서 y가 가까운 가사 밴드들 = 같은 시스템의 1/2/3절
5. **재조립** — 각 스태프의 "N번째 가사 밴드" 들을 x 좌표 순으로 이어붙이면 N절 완성

## 실행 흐름

### Step 1: 대상 곡 확인

사용자에게:

> 어떤 곡의 가사를 추출할까요?
> - 곡 번호 (예: 5)
> - 범위 (예: 1~50)
> - "전부" → 495곡 전체
> - "미매칭" → 크롤링/기존 DB에 없는 곡만

### Step 2: PDF 페이지 매핑

각 대상 곡에 대해:
- 제목을 정규화하여 검색 (공백/하이픈 제거)
- 페이지의 첫 200자에 곡 번호가 있으면 가산점
- 가장 높은 점수의 페이지를 선택

### Step 3: 위치 기반 텍스트 추출

각 페이지에 대해:
- `page.get_text("dict")`로 span별 (x, y, text, font_size) 수집
- y 좌표 클러스터링 (gap_threshold=7.0)
- 스태프 시스템 그룹화 (staff_gap=35.0)
- 각 스태프 내 가사 밴드 필터링 (한글 포함, font ≤ 15pt, 항목 ≥ 3)

### Step 4: 절별 재조립

각 스태프에서 n번째 가사 밴드 = n절.
- 스태프 간 같은 절 번호의 밴드를 이어붙여 전체 절 완성
- 각 밴드 내부는 x 좌표 오름차순 정렬
- 하이픈(`-`) 정리, 연속 공백 축소

### Step 5: 페이지 경계 처리

다절 곡이 여러 페이지에 걸칠 수 있음:
- 다음 페이지 상단 200자에 현재 곡 번호 + 1이 없으면 같은 곡의 연속으로 간주
- 연속 페이지의 절별 결과를 이어붙임

**주의:** 한 페이지에 2곡이 있는 경우(page 5, page 4 등) 다음 곡 내용이 섞일 수 있음. 곡 번호 경계 검출 정확도가 결과 품질의 핵심.

### Step 6: 결과 저장

JSONL 형식으로 한 줄씩:
```json
{"번호": 5, "제목": "거룩하다 부활이여", "pdf_page": 5,
 "절별": {"1절": "...", "2절": "...", "3절": "...", "4절": "..."}}
```

### Step 7: 품질 신뢰도 표시

각 곡마다 자동 신뢰도:
- **높음**: 절 개수 2개 이상, 각 절 50자 이상, 한글 비율 90%+
- **중**: 절 개수 1개 또는 일부 짧음
- **낮음**: 전체 가사 50자 미만, 페이지 오염 의심

## 주의사항

- **PDF 텍스트 레이어가 있어야 함**. 스캔 PDF는 OCR 필요 (별도 스킬)
- **악보 가사는 음절 단위로 배치**되어 있어, 읽는 순서가 악보 순서와 다를 수 있음. x 좌표 정렬이 핵심
- **하이픈 처리**: 가사에서 음절 연결 하이픈(`빛-나게-`)은 제거, 필요 시 공백으로 대체
- **다절 스택**: 1절/2절/3절이 같은 스태프에 세로로 쌓인 경우, y 좌표 미세 차이로 구분
- **결과는 검증 대상**: 자동 추출이므로 반드시 사용자 검토 필요. 특히 페이지 경계 주변

## 향후 개선 방향

1. **페이지 경계 엄격화**: 곡 번호 레이블의 정확한 x, y 좌표로 페이지를 "곡 영역"으로 분할
2. **코드/음표 제거**: 코드 심볼(C, Dm, Bb 등)이 가사 밴드에 섞이는 경우 필터
3. **후렴 감지**: 반복 기호(`Fine`, `D.C.`)와 함께 등장하는 가사를 후렴으로 분리
4. **영어/라틴어 가사**: 한글 필터를 조건부로 변경
