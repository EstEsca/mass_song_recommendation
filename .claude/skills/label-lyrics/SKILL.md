# 가사 라벨링 스킬

곡정보.xlsx의 가사 본문을 LLM(현재 세션)이 읽고 다음 3축의 라벨을 제안한다:
- **요약**: 40~60자 가사 요지 (스칼라)
- **느낌**: vocab 제약 — 활기찬·장엄한·서정적·고요한·기쁜·애원하는·선포·묵상적
- **키워드**: 자유 (가사 핵심어, 신학 주제, 인물·장소 등)

`색인.성경`·`색인.시기`·`색인.대축일` 등은 다루지 않음(이미 마이그레이션에서 일부 채워졌고, 추가는 [/add-tag](../add-tag/SKILL.md) 또는 엑셀 직접 편집).

## 정책

- **자동 채움 금지** ([feedback_no_auto_field_fill](../../../docs/tracker/CONSIDERATIONS.md)) — 사용자 명시 호출 시에만 실행
- **결과는 항상 사용자 검토 후 적용** — 표로 보여주고 승인받기
- **vocab 위반은 거부**(느낌 8개 외 값은 적용 안 함)
- **이미 요약이 있는 곡은 기본 skip** (덮어쓰기는 명시 요청 시만)

## 데이터 흐름

```
곡정보.xlsx (가사 시트 + 곡목록 시트)
    │ 읽기
    ▼
LLM 분석 (현재 Claude 세션)
    │ jsonl 산출 (메모리 또는 임시 파일)
    ▼
사용자 검토 (표 형식)
    │ 승인
    ▼
scripts/apply_labels.py
    │ 곡정보.xlsx의 요약 + 색인 시트에 반영
    ▼
사용자가 python scripts/rebuild.py 실행
```

## 실행 흐름

### Step 1: 대상 곡 파싱

`$ARGUMENTS` 해석:
- `5` → 단일 곡
- `1-10`, `30~50` → 범위
- `32 38 50` → 복수 번호
- `미라벨` 또는 인자 없음 → **요약 시트 B열이 비어있는 곡** (이미 라벨된 곡 skip)

대상 곡 수가 **20개를 초과**하면 사용자에게 확인 (한 세션에서 LLM 호출 비용이 큼). 권장 배치: 5~15곡.

### Step 2: 가사 로드

- 곡정보.xlsx가 엑셀로 열려 있으면 잠금 위험 — Read-only 모드로 시도 후 실패 시 안내
- 또는 더 간단히 `data/songs.json`에서 v2 곡 객체 읽기 (`가사` 필드는 단일 문자열)
- 가사가 비어있는 곡은 라벨링 불가 → skip + 보고

### Step 3: LLM 라벨링 (곡당)

각 곡의 가사 본문을 읽고 아래 형식으로 출력:

```jsonc
{
  "번호": 1,
  "제목": "가서 내 형제들에게 전하여라",
  "요약": "부활하신 예수께서 제자들에게 갈릴래아로 가 만남을 전하라 하심",
  "느낌": ["활기찬", "선포"],
  "키워드": ["부활", "갈릴래아", "사명", "목자"]
}
```

**프롬프트 원칙**
- "가사 본문만" 기반으로 판단. 외부 검색 금지.
- 요약은 **40~60자 한국어 평서문**. 마침표 1개. 가사의 핵심 신학적 메시지·내러티브 요약.
- 느낌은 vocab 8개 중에서만. 곡당 0~3개. 확신 없으면 비움.
- 키워드는 **가사 표면어**(예: 갈릴래아·목자) + **신학 주제**(예: 부활·회개). 곡당 3~7개. 중복·유사어 정리.
- 불확실한 항목은 빈 배열로 두는 것이 과태깅보다 낫다.

### Step 4: 사용자 검토

표로 출력:

```
## 📋 라벨링 제안 (N곡)

| 번호 | 제목 | 요약 | 느낌 | 키워드 |
|------|------|------|------|--------|
| 1 | 가서 내 형제들에게 전하여라 | 부활하신 예수께서... | 활기찬·선포 | 부활·갈릴래아·사명·목자 |
| 2 | 가자 갈릴래아로! | ... | ... | ... |
```

> 위 N곡 라벨을 적용할까요?
> - 전부 승인 / 일부 승인 (번호) / 개별 수정 / 취소

### Step 5: 임시 jsonl 저장

승인된 항목만 `data/source/labeling_proposals/{타임스탬프}.jsonl`에 저장.

### Step 6: 적용

```bash
python scripts/apply_labels.py data/source/labeling_proposals/<file>.jsonl
```

옵션:
- `--force` : 기존 요약 덮어쓰기 (기본은 skip)
- `--dry-run` : xlsx 변경 없이 결과 미리보기

### Step 7: 결과 보고

`apply_labels.py` 출력을 그대로 사용자에게 전달:
- 요약 적용 N곡 / skip / 행 없음
- 느낌 추가 N건 / 중복 / vocab 위반
- 키워드 추가 N건 / 중복

마지막에 `python scripts/rebuild.py` 실행 안내.

## 토큰·시간 예산

- 곡당 LLM 입력: 가사 ~200~400 토큰 + 시스템 프롬프트 ~200 토큰 = ~500 토큰
- 곡당 출력: ~80 토큰
- 10곡 배치: 입력 ~5K + 출력 ~1K = **~6K 토큰**
- 권장: 한 세션에 **10~15곡**, 큰 작업은 여러 세션으로 분할

## 데이터

- 입력: `data/songs.json` (가사 본문) — Read 도구로 직접 읽기
- 임시 산출물: `data/source/labeling_proposals/{타임스탬프}.jsonl`
- 최종 반영: `data/source/곡정보.xlsx`의 `요약`·`색인` 시트 (apply_labels.py)

## 원칙

- **xlsx만 수정** — songs.json 직접 갱신 금지 (다음 rebuild에 덮어쓰여짐)
- **제안만, 자동 덮어쓰기 금지** — 항상 사용자 승인 관문 통과
- **vocab 엄격 적용** — 느낌은 vocab 외 값 거부
- **외부 호출 없음** — LLM은 현재 Claude 세션 내에서만

## 보조 근거: 템포·박자·장르 (2026-11-05 추가)

가사만으로 **느낌**을 정하면 빠르기를 놓친다. 다음을 보조 근거로 쓰고, 근거 란에 `템포 ♩=NN → …`처럼 남긴다.

| 신호 | 기울이는 느낌 |
|---|---|
| 가사 머리말 `♩=NN`·`4분음표=NN`·머리말 숫자, ♩ ≤ 72 | 고요한 · 묵상적 · 서정적 · 애원하는 |
| 73 ~ 95 | 중립 — 가사로 판단 |
| 96 ~ 115 | 활기찬 · 기쁜 · 선포 |
| ≥ 116 | 활기찬 |
| 박자 6/8 · 3/4 · 12/8 | 서정적 쪽 |
| 떼제 반복곡, 미사통상문 | 떼제는 고요한·묵상적, 미사곡은 악보 없이 판단 불가 → 비움 |

가사 손상(띄어쓰기 없음·글자 깨짐·조각)으로 요지를 읽을 수 없으면 **SKIP**하고 사유를 근거에 적는다. 억지로 달지 않는다.

## 자동 진행 모드

사용자가 "나머지는 자동으로 진행"처럼 명시하면 배치(50곡)마다 승인 관문을 생략할 수 있다. 대신 다음을 지킨다.

- 배치마다 커밋을 분리: 라벨 적용 / 구조 태그(성경·시기·대축일) 추가 / 오탈 태그 제거. 각 커밋이 revert 단위.
- 승인 jsonl(`data/source/labeling_proposals/{날짜}_batch_{범위}.jsonl`)에 `근거`를 포함해 커밋. 검토용 `review_*.md`는 gitignore.
- 요약 40~60자, 느낌 ≤3, 키워드 3~7을 스크립트로 검증한 뒤에만 적용.
