# ADR-007: 스키마 v2.1 — 곡 비고 부활 + 음악 메타데이터 확장

**상태:** 채택 (2026-04-29)
**대체 ADR:** 없음 (v2.0 호환 minor 확장)
**관련 ADR:** [ADR-006: 스키마 v2.0 전환](ADR-006-schema-v2.md)

## 맥락

v2.0(2026-04-25)은 색인·가사 중심으로 스키마를 재정의하면서 두 가지를 의도적으로 비웠다.

1. **곡 단위 자유 메모**: v1의 `색인.비고`는 EAV 색인에 어울리지 않아 폐기됨. 그러나 운영 중 곡 단위로 사용자가 남기는 메모(편곡 주의, 사용 추천 시점 등)가 자주 필요했다.
2. **곡 자체의 음악적 메타데이터**: 조표·박자 등은 v2.0 범위 밖. 선곡 실무에서 반복적으로 필요한 정보였다.

S-007 스프린트(2026-04-25 활성화)에서 이 세 가지를 v2.1로 묶어 도입하기로 합의했다 — 모두 곡 단위 단일값(스칼라)이며 `곡목록` 시트의 wide 확장으로 흡수 가능.

## 결정

### 추가 필드

| 필드 | 위치 | 타입 | 표기 예 |
|---|---|---|---|
| `비고` | `songs.json` 곡 객체 / `곡목록` 시트 | `str` | `"3절은 반주만"`, 비어있으면 `""` |
| `조표` | `songs.json` 곡 객체 / `곡목록` 시트 | `int \| null` | `+3`, `0`, `-2` (정수, +N=샤프 N개, -N=플랫 N개) |
| `박자` | `songs.json` 곡 객체 / `곡목록` 시트 | `str` | `"4/4"`, `"3/4"`, `"6/8"`, `"2/2"` |

### 비고 부활 — 위치 변경

v1: `색인.비고` (색인 객체 안). EAV 색인 모델로 가면서 의미적으로 어울리지 않아 v2.0에서 폐기.
v2.1: **곡 최상위 `비고`** (제목·작곡자와 동등 레벨). 색인 카테고리가 아닌 **곡 단위 자유 메모**임을 명확히 한다. 빈값은 `""`.

### 표기 컨벤션 — 조표

**정수만 저장**. `+`/`-` 부호로 샤프/플랫 개수를 표현. 모드(major/minor)는 **저장하지 않음** — 가창자가 멜로디로 즉시 판별 가능하고, 조성 추정 알고리즘의 minor↔major 혼동 비용을 피하기 위함.

| 정수 | 의미 | 동등 키 |
|---:|---|---|
| `+7` | 샤프 7개 | C# major / A# minor |
| `+3` | 샤프 3개 | A major / F# minor |
| `+1` | 샤프 1개 | G major / E minor |
| `0` | 무 | C major / A minor |
| `-1` | 플랫 1개 | F major / D minor |
| `-3` | 플랫 3개 | E♭ major / C minor |
| `-7` | 플랫 7개 | C♭ major / A♭ minor |
| `null` | 미확인 | — |

**대안 검토 후 기각**:
- A. 영문 음명+모드 (`G`, `Em`) — 한글 사용자 친숙도 낮음, 모드 구분 비용.
- B. 한글 조명 (`사장조`) — 입력 오류 잦음, 길고 변환 단계 필요.
- C. 혼합(저장은 영문, 표시는 한글) — 변환 테이블 유지보수 부담.

선택지 D(정수)는 **저장 효율 + 정렬 가능 + 모드 비저장**으로 단순함. 뷰어에서 한글 조명 변환은 사용자가 필요 시 추가.

### 표기 컨벤션 — 박자

**분수 문자열** (`"분자/분모"`). 박자 변화 곡은 주박자만 1개 저장. 박자 vocab은 자주 쓰이는 8~10개로 시작:
`"2/4"`, `"3/4"`, `"4/4"`, `"6/8"`, `"9/8"`, `"12/8"`, `"2/2"`, `"3/2"`.

vocab 외 값은 허용하되 `_meta.warnings`에 기록(향후 확장 여지).

### null·빈값 정책

| 필드 | 미확인 표현 | 비고 |
|---|---|---|
| `조표` | `null` | **v2.0 "no null" 규칙의 의도적 예외**. 이유: `0`이 다장조라는 의미를 가져 빈값 표현으로 못 씀. |
| `박자` | `""` (빈 문자열) | 다른 스칼라 문자열 필드(`요약`·`가사`)와 동일 규칙 |

xlsx에서는 둘 다 빈 셀이 미확인. `build_songs_json.py`가 변환:
- `조표` 빈 셀 → JSON `null`
- `박자` 빈 셀 → JSON `""`

### xlsx 시트 변경

`곡목록` 시트(Wide)에 컬럼 3개 추가. 색인·가사·요약 시트는 무영향.

```
변경 전: 번호 | 제목 | 작곡자 | 분류
변경 후: 번호 | 제목 | 작곡자 | 분류 | 비고 | 조표 | 박자
```

### 데이터 수집 경로

자동 추출 → 사용자 검토 → xlsx 병합의 3단계.

1. **Audiveris OMR (winget 설치, JRE 25 번들)** — PDF의 모든 시트를 OMR하여 MusicXML 출력. 조표·박자 동시 추출. (5시트 시범 100% 추출 확인.)
2. **music21 코드 심볼 키 분석** — Audiveris 결과 교차 검증용 (102곡 고신뢰 ≥0.85).
3. **임시 CSV** (`data/raw/조표_자동추정.csv`, `data/raw/박자_자동추정.csv`) → 사용자 검토 → `apply_keysig.py`/`apply_meter.py`로 xlsx 병합.

OMR 실패·저신뢰 곡은 사용자가 xlsx에서 직접 입력 (495 × ~3초).

### schema_version 범프

v2.0 → **v2.1** (호환 가능한 확장). `metadata.schema_version` 필드 갱신.

## 대안 (기각)

### A. 새 시트 `음악정보` 추가

**기각 이유**: 곡 1:1 단일값 필드는 `곡목록`과 동일한 구조. 새 시트는 join 비용만 늘림.

### B. `색인` 시트(Tall)에 `타입="조표"` 추가

**기각 이유**: Tall 형식은 다중값·다중 카테고리 태그용. 단일 스칼라(곡당 1개) 필드를 EAV로 저장하면 의미적으로 어울리지 않고 `groupby(번호)` 합성 시 단일값 보장도 까다로워짐.

### C. 빠르기·음역도 같이 도입

**기각 이유**: 빠르기 표기 vocab(이탈리아어/한글/BPM) 합의 비용, 음역은 OMR로 수집 가능하지만 정확도 검증 부담 큼. 우선 조표·박자만으로 1차 사이클 닫고, 사용 데이터 보고 다음 스프린트에서 재검토.
