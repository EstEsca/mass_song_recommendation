# ADR-004: 외부 호출 정책

**일자:** 2026-04-16
**상태:** 채택

## 맥락

이전 구현에서 /find-lyrics와 /repair-lyrics가 WebFetch/WebSearch를 적극 활용했으나:
- 저작권 이유로 가사 반환 거부 빈번 → 토큰 낭비
- 한 실행에 수십 건의 웹 호출 → 비용 큼
- 사용자 의도와 별개로 자동 실행됨 → 통제감 부족

robots.txt 준수 크롤러(ADR-001)로 가사 확보가 가능한 범위(maria.catholic.or.kr 173곡)는 이미 확보됨.

## 결정

**외부 호출은 명시 요청 시에만 실행.**

### 정책 요약
- 🟢 **로컬 호출(Read/Write/Bash/Python)**: 자유
- 🟡 **중간 비용(WebFetch 1~2회)**: 필요 시 실행 가능
- 🔴 **고비용(WebSearch 다회, 병렬 WebFetch)**: 사용자가 명시적으로 요청할 때만

### 구체 적용
- `/find-lyrics`: 1차(로컬 DB) → 2차(PDF 추출) 기본. 3차(웹) 스킵 → **사용자 승인 시에만 실행**
- `/repair-lyrics`: 기본 실행 금지. **명시 호출 시에만 작동**
- `/extract-sheet-lyrics`: 외부 호출 **완전 금지** (로컬 PDF만)
- `/validate-lyrics`: 외부 호출 **완전 금지** (로컬 체크만)

### 크롤러는 별도
- 수동 실행되는 크롤러(`crawl_maria.py` 등)는 이 정책 대상 아님
- 크롤러는 robots.txt 준수로 제한 (ADR-001 재확인)

## 대안

1. **제한 없이 자유롭게 호출** — 기각 (토큰 비용 폭증)
2. **모든 외부 호출 금지** — 기각 (필요 시 유연성 상실)
3. **자동 호출 + 예산 제한** — 기각 (사용자 통제감 중요)

## 결과

**긍정:**
- 토큰 소모 예측 가능
- 사용자가 통제권 유지
- 기본 흐름은 로컬 데이터만으로 작동 → 빠르고 저렴

**부정:**
- 사용자가 때때로 "웹 검색으로 보완해줘"를 명시해야 함
- 자동화 수준 감소 (의도적)
