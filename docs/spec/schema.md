# 데이터 스키마 (Single Source of Truth)

**상태:** 채택 (2026-04-25)
**버전:** v2.1 (2026-04-29 비고 부활 + 음악 메타 확장)

프로젝트의 모든 데이터 파일의 **공식 스키마**. 모든 스킬과 스크립트는 이 문서를 기준으로 작동해야 한다.

v1.0 → v2.0 주요 변경: ADR-006 참조. 스키마·편집 경로·파생 파이프라인을 한 번에 재정의했다.
v2.0 → v2.1 변경: ADR-007 참조. (1) v2 마이그레이션 시 폐기됐던 곡 비고를 곡 최상위 필드(`비고`)로 부활. (2) 곡 음악 메타 `조표`(int|null)·`박자`(str) 추가.

## 3계층 데이터 분업

```
[편집 계층 — 사람]                  [SSoT 계층 — 스킬]            [뷰 계층 — 빠른 색인]
data/source/곡정보.xlsx             data/songs.json               data/songs_index.json
  ├ 시트 "곡목록"           build      (JSON, 스킬이 Read)   build     (JSON, 가사 제외 경량)
  ├ 시트 "요약"         ────────▶                        ────────▶
  ├ 시트 "색인" (tall)                                                         │
  └ 시트 "가사"                                                                │ 런타임
                                                                               ▼ Python이
                                                                         Wide TSV 직렬화
                                                                               │
                                                                               ▼
                                                                       [LLM 입력 — 프롬프트]
```

| 계층 | 파일 | 편집 가능 | 목적 |
|---|---|---|---|
| 편집 | `data/source/곡정보.xlsx` | ✅ 사람(엑셀) + 에디터 | 단일 SSoT 편집 포인트 |
| SSoT | `data/songs.json` | ❌ 파생물 | 스킬이 구조적으로 접근 |
| 뷰 | `data/songs_index.json` | ❌ 파생의 파생 | 1차 후보 필터 고속 탐색 |
| LLM 입력 | 런타임 Wide TSV 문자열 | — | 토큰 최소 포맷 |

**불변 원칙**
- 사람이 편집하는 파일은 `data/source/곡정보.xlsx` **하나뿐**
- `songs.json`·`songs_index.json`은 사람이 직접 수정하지 않는다 (다음 빌드에 덮어쓰여짐)
- 각 파생물 상단 `_meta.built_from_sha256` + `built_at`으로 원본과 동기화 검증

```
│   ├── source/

│   ├── archive/

│   ├── songs.json                   # 파생: 스킬 소비용 JSON
│   └── songs_index.json             # 파생의 파생: 경량 색인
└── scripts/
    ├── migrate_v1_to_v2.py          # 1회: v1 songs.json → v2
    ├── export_to_xlsx.py            # 1회: v2 songs.json → 곡정보.xlsx
    ├── build_songs_json.py          # 상시: 곡정보.xlsx → songs.json
    ├── build_song_index.py          # 상시: songs.json → songs_index.json
    ├── rebuild.py                   # 상시: 위 2개 일괄 실행
    ├── serialize_candidates.py      # 런타임: 후보 JSON → Wide TSV
    └── filter_candidates.py         # 런타임: 1차 후보 필터 (experimental)
```

## 곡정보.xlsx 시트 구조

**파일**: `data/source/곡정보.xlsx` 단일 파일, 시트 4개.

| 시트 | 형식 | 컬럼 | 행 수 |
|---|---|---|---|
| `곡목록` | Wide | 번호·제목·작곡자·분류·비고·조표·박자 | ~495 |
| `요약` | Wide | 번호·요약 | ~495 |
| `색인` | **Tall (EAV)** | 번호·타입·값 | ~4,000 (495 × 평균 8태그) |
| `가사` | Wide | 번호·가사 | ~495 |

**공통 규칙**
- 모든 시트 `번호` 컬럼을 키로 조인
- 모든 셀 서식 **텍스트** (날짜·숫자 자동 변환 방지)
- Excel Table 기능으로 각 시트를 Table로 지정 (필터·정렬 기본 제공, 빌드 스크립트가 Table 이름으로 접근)
- 인코딩: xlsx 네이티브 (UTF-8 내부)

### 시트 `색인` (Tall / EAV 형식)

한 행 = 한 태그. `타입` 컬럼은 **7개 고정 카테고리**만 허용(아래 참조). `값` 컬럼은 타입에 따라 vocab 제약이 다르다.

예시:
```
번호 | 타입    | 값
1    | 성경    | 마태28:16-20
1    | 성경    | 요한20:19-23
1    | 시기    | 부활
1    | 역할    | 파견
1    | 느낌    | 활기찬
1    | 느낌    | 선포
1    | 키워드  | 갈릴래아
2    | 시기    | 부활
...
```

**Tall 형식을 선택한 이유**
- 태그 추가·삭제가 **행 조작**(한 셀 = 한 값, 실수 감소)
- 엑셀 필터(`타입=성경`)로 특정 카테고리만 조망 쉬움
- 사용자의 "로그 남겨가며 태그 추가" 워크플로우와 정합
- 빌드 스크립트는 `groupby(번호)`로 JSON 합성

### 최상위 구조

```json

    "created": "YYYY-MM-DD",
```

```json

  "번호": 1,
  "제목": "가서 내 형제들에게 전하여라",
  "작곡자": "M. J. Huston",
  "분류": "성가",
  "비고": "",
  "조표": 1,
  "박자": "4/4",
  "색인": {
    "요약": "부활하신 예수께서 제자들에게 갈릴래아로 가 만남을 전하라 하심",
    "성경":  ["마태28:16-20", "요한20:19-23"],
    "성월":  [],
    "시기":  ["부활"],
    "대축일": [],
    "역할":  ["파견"],
    "느낌":  ["활기찬", "선포"],
    "키워드": ["갈릴래아", "사명", "목자", "부활"],
    "곡모음집": ["가톨릭성가"]
  },
  "가사": "가서 내 형제들에게 전하여라\n갈릴래아로 갈릴래아로 떠나거라\n..."
}
```

### 필드 명세

| 필드 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| `번호` | int | ✓ | 청소년청년성가집 곡 번호 (1~495) |
| `제목` | str | ✓ | 정식 제목 |
| `작곡자` | str | ✓ | 작곡자/작사자 |
| `분류` | str | ✓ | `성가` 또는 `미사곡` |
| `비고` | str | ✓ | 곡 단위 자유 메모 (v2.1에서 부활). 비어있으면 `""` |
| `조표` | int \| null | ✓ | 부호 있는 정수. `+N`=샤프 N개, `-N`=플랫 N개, `0`=다장조/가단조. 미확인이면 `null` (v2.0 "no null" 규칙의 의도적 예외 — 0이 다장조라는 의미를 가지므로) |
| `박자` | str | ✓ | 분수 문자열. 예: `"4/4"`, `"3/4"`, `"6/8"`, `"2/2"`. 박자 변화 곡은 주박자 1개. 미확인이면 `""` |
| `색인.요약` | str | ✓ | 40~60자. 가사 요지. 비어있으면 `""` |
| `색인.성경` | list[str] | ✓ | 관련 성경 구절, 정규화 키 형식 |
| `색인.성월` | list[str] | ✓ | 숫자월(`"5월"`, `"10월"` 등) |
| `색인.시기` | list[str] | ✓ | 5개 전례시기 vocab만 |
| `색인.대축일` | list[str] | ✓ | 공식 대축일명 |
| `색인.역할` | list[str] | ✓ | 미사 순서 vocab만 |
| `색인.느낌` | list[str] | ✓ | 분위기 vocab만 |
| `색인.키워드` | list[str] | ✓ | 자유 태그 |
| `색인.곡모음집` | list[str] | ✓ | 곡이 수록된 성가집/곡집명 (예: `가톨릭성가`, `야훼이레`) |
| `가사` | str | ✓ | 본문 전문 (비어있으면 `""`) |

**모든 배열은 비어있어도 `[]`.** `null` 금지 (예외: `조표`만 미확인을 `null`로 표현). 스칼라 문자열 필드(`비고`·`요약`·`박자`·`가사`)는 비어있으면 `""`.

## 성경 키 정규화 규칙

**형식**: `{책약어}{장}:{절시작}-{절끝}`

- 공백 없음, 한글 책 약어, 장과 절 사이 `:`, 절 범위 `-`
- 단일 절: `"마태5:3"` (절시작==절끝이면 `-끝` 생략)
- 장 전체: `"시편23"` (절 생략)
- 여러 장·불연속 구간: **여러 엔트리로 분리**. 쉼표 연속 금지

**허용 책 약어** (한국천주교주교회의 공식 약어)

구약: 창·탈·레·민·신·여·판·룻·1사·2사·1열·2열·1역·2역·에즈·느·토빗·유딧·에스·1마카·2마카·욥·시편·잠·코헬·아가·지혜·집회·이사·예레·애가·바룩·에제·다니·호세·요엘·아모·오바·요나·미카·나훔·하박·스바·하깨·즈카·말라

신약: 마태·마르·루카·요한·사도·로마·1코린·2코린·갈라·에페·필리·콜로·1테살·2테살·1티모·2티모·티토·필레·히브·야고·1베드·2베드·1요한·2요한·3요한·유다·묵시

**예시 변환**

| v1 표기 | v2 정규화 |
|---|---|
| `"마태 28, 16-20"` | `"마태28:16-20"` |
| `"마태 28, 16-20\n마르 16, 14-18"` | `["마태28:16-20", "마르16:14-18"]` |
| `"시편 23"` | `"시편23"` |
| `"요한 6, 51"` | `"요한6:51"` |

## null 원칙

v1에서는 미채움을 `null`로 표현했다. **v2에서는 빈 배열(`[]`) 또는 빈 문자열(`""`)로 통일**.

- 배열 필드: `null` 금지, 비어있으면 `[]`
- 스칼라 문자열(`비고`·`요약`·`박자`·`가사`): `null` 금지, 비어있으면 `""`
- 파서가 `null` 만나면 오류로 처리

이유: 타입 일관성 + Python/JavaScript에서 안전 반복(`for x in []` OK, `for x in None` 예외).

### 예외: `조표`

`조표`는 정수 필드인데 `0`이 "다장조/가단조(샤프·플랫 0개)"라는 음악적 의미를 가지므로 빈값 표현으로 못 쓴다. **미확인은 `null`로 표현한다.**

- xlsx 빈 셀 → JSON `null`
- 사용자 입력값이 `0` → 다장조/가단조로 해석
- 파서가 `조표` 필드만은 `null` 허용 (다른 필드 `null`은 여전히 오류)

## songs_index.json 스키마 (뷰 계층)

```json
{
  "metadata": {
    "built_from_sha256": "<songs.json의 sha256>",
    "built_at": "YYYY-MM-DDTHH:MM:SS",
    "total_songs": 495
  },
  "songs": {
    "1": {
      "번호": 1,
      "제목": "...",
      "작곡자": "...",
      "분류": "성가",
      "색인": { /* songs.json과 동일 */ }
    }
  }
}
```

`가사` 필드 **제외**. 나머지는 songs.json과 동일. 1차 후보 필터에서만 읽고, 본문이 필요하면 songs.json으로 pinpoint 조회.

## 설계 원칙

- **번호 문자열 키**: `"1"`, `"2"` (JSON 관례)
- **파생 계층은 사람 편집 금지**: songs.json · songs_index.json 직접 수정 시 다음 빌드에 덮어쓰여짐
- **저작권 보호 데이터**: `songs.json`, `곡정보.xlsx`는 `.gitignore`로 제외. textconv는 로컬 git diff용
- **색인 자동 보완 금지**: 정책 `feedback_no_auto_field_fill.md` — 사용자 명시 요청 시에만 LLM 라벨링

## 스키마 변경 정책

### 버전 번호 규칙
- **Major (x.0)**: 기존 데이터 호환 불가. 마이그레이션 필요 (v1→v2 같은 경우)
- **Minor (2.x)**: 호환 가능한 확장 (필드 추가, 선택적 필드)
- **Patch (2.0.x)**: 문서 정정, 주석 추가 (데이터 영향 없음)

### 변경 절차
1. **ADR 작성**: `docs/spec/decisions/ADR-NNN-schema-change.md`에 변경 이유/내용 기록
2. **schema.md 갱신**: 이 문서에 새 버전 스키마 반영
3. **`metadata.schema_version` 업데이트**
4. **관련 스킬/스크립트 갱신**
5. **곡 객체 전체 마이그레이션** (Major의 경우)
