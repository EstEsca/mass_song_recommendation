# 스킬 설계/사용 정책

**상태:** 채택 (2026-04-16)

가사 관련 스킬들의 역할과 경계, 외부 호출 기준을 명시한다.

## 스킬 역할 지도

```
┌─────────────────────────────────────────────────┐
│ /extract-sheet-lyrics  [1차 추출, 로컬]         │
│  PDF 텍스트 레이어 → songs.json 가사 필드        │
│  외부 호출: 없음                                 │
└──────────────┬──────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────┐
│ /validate-lyrics  [형식 검증, 로컬]              │
│  songs.json → 형식 위반 리포트                   │
│  외부 호출: 없음                                 │
└──────────────┬──────────────────────────────────┘
               │
               ▼ (명시 요청 시)
┌─────────────────────────────────────────────────┐
│ /repair-lyrics  [웹 기반 복구, 고비용]          │
│  어색 구간 → WebSearch 스니펫으로 복구           │
│  외부 호출: WebSearch 多. 명시 요청 시에만      │
└─────────────────────────────────────────────────┘

/find-lyrics  [오케스트레이터]
  ↓ 위 세 스킬을 단계별로 호출. 각 단계에서 사용자 승인
```

## 외부 호출 비용 분류

| 등급 | 설명 | 예시 | 스킬 정책 |
|------|------|------|----------|
| 🟢 로컬 | 파일 읽기/쓰기, Python | Read/Write/Bash | 자유 |
| 🟡 중간 | 단일 웹 요청 | WebFetch 1회 | 필요 시 실행 |
| 🔴 고비용 | 다중 웹 요청 | WebSearch 다회, 병렬 WebFetch | **명시 요청 시에만** |

## 각 스킬의 외부 호출 정책

### /extract-sheet-lyrics
- **외부 호출: 금지**
- 로컬 PDF 처리와 songs.json 갱신만 수행
- maria 교차 검증 등은 이 스킬에서 하지 않음

### /validate-lyrics
- **외부 호출: 금지**
- songs.json을 읽어서 형식 스펙(`docs/spec/lyrics_format.md`) 기준으로 로컬 검증

### /repair-lyrics
- **외부 호출: 명시 요청 시에만**
- `Step 0` 에서 사용자 재확인 필수
- 한 번 실행 시 대상 곡 수 명시 필요
- 에이전트당 최대 2곡, 동시 최대 5개

### /find-lyrics
- **외부 호출: 단계별 사용자 승인**
- 1차(로컬 DB) → 2차(PDF 추출) → 3차(웹) 순서
- 3차는 기본 스킵, 사용자 명시 요청 시에만

## 행잉 방지 가이드

### 에이전트 배치
| 스킬 | 에이전트당 곡 수 | 동시 에이전트 최대 |
|------|----------------|------------------|
| extract-sheet-lyrics | 30~50 (가벼움) | 5 |
| validate-lyrics | 50~100 (순수 로컬) | 5 |
| repair-lyrics | 2 (무거움) | 5 |
| find-lyrics | 10 (중간) | 10 |

### 조기 종료 규칙
- WebFetch 거부 시 **반복 시도 금지**, 다음 소스로 이동
- 한 소스당 최대 1회 재시도
- 에이전트 전체 WebFetch 호출 ≤ 30회 권장

### 200곡 이상 대량 처리
1. 로컬 DB 일괄 매칭 (Python, 수초)
2. 미매칭 곡만 웹 검색 (필요 시)
3. 라운드 분할 (1라운드 완료 후 2라운드)

## 데이터 접근 정책

모든 스킬은 다음을 따른다:

- **입력/출력: `data/songs.json`** (schema.md 준수)
- **직접 스키마 위반 금지**: 새 필드 추가 시 schema.md 먼저 갱신
- **저작권 자료 대화 출력 금지**: 로컬 파일로만 저장, 대화창에 가사 전문 출력 제한
