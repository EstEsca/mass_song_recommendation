# S-003: 가사 완전 복구 및 DB화

**상태:** 완료 (목표 부분 달성 — 잔여 작업은 이슈 #41·#42으로 분리)
**기간 시작:** 2026-04-20
**기간 종료:** 2026-11-04

## 목표

493곡(현재 확보분) + 2곡(영어곡) = 495곡 전체의 가사를 **최종 품질 수준**으로 복구하여 선곡 추천에 쓸 수 있는 DB로 완성.

### 핵심 원칙

1. **사용자가 권위 있는 소스**에서 가사를 수동 입력 (합법 보유 자료 사용)
2. **Claude는 형식 보정만** 담당 (띄어쓰기, 마커 변환, 절 분리, 절구조 재생성)
3. **가사 본문은 사용자 또는 크롤링 원본에서만** 유입, Claude가 새로 생성/추정하지 않음

## 완료 기준

| 기준 | 목표 |
|------|------|
| 가사 확보율 | 495 / 495 (100%) |
| 형식 통과율 | ≥ 95% (≥ 470곡) |
| 사용자 수동 입력 곡 | 추적 가능 (출처 필드에 "수작업" 표시) |
| 선곡 추천 동작 확인 | `/recommend-hymns` 실전 테스트 통과 |

```
[대상 곡 식별]
   ↓
```

## 회고

### 잘된 점
- "가사를 다 모은다"는 큰 목표를 S-002(PDF 추출)·S-006(소스 확장)으로 쪼개 실행한 결과 2주 만에 35% → 99.6%. 우산 스프린트로서 역할을 했음.

### 아쉬운 점
- 우산 스프린트가 하위 스프린트 완료 뒤에도 "보류"로 남아 트래커를 흐렸음. 하위 스프린트가 목표를 흡수하면 우산은 그 시점에 닫아야 했음.
- `/structure-lyrics`(절·후렴 구조 추론)는 DRAFT 상태로 미구현. 그러나 반년간 모드 A 추천이 구조 없이도 동작했으므로 실수요가 검증되지 않음. 구현 여부는 fail case가 나올 때 판단.

### 교훈
- 완료 기준을 "100%"로 두면 영원히 닫히지 않는다. 운영에 충분한 수준(이번엔 99.6%)을 종료 기준으로 재정의하고 잔여는 이슈로 내린다.
