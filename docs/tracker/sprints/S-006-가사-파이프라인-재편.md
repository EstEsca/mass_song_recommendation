# S-006: 가사 파이프라인 재편 — 크롤링 소스 확장 + 정리 스킬 분리

**상태:** 완료
**기간 시작:** 2026-04-24
**기간 종료:** 2026-04-25

## 목표

1. **maria 외 합법적 가사 소스를 추가**하여 청소년청년성가집의 고신뢰 커버리지를 대폭 끌어올린다.
2. **크롤링 스킬 구조를 사이트별 전략으로 재편**해 앞으로 소스를 추가·교체하기 쉽게 만든다.
3. **단일 진리 저장소 원칙**을 확립하고, 크롤러가 `songs.json`을 안전하게 in-place 병합하도록 재설계한다.
4. **`/fix-lyrics-format`의 책임 과잉 문제**를 해결하기 위해 본문 정리(`/clean-lyrics`)와 절 구성 추론(`/structure-lyrics`)으로 분리한다.

### 핵심 결정 사항

1. **yseng.kr 조사·편입** — 30~500번 중 maria 미확보 302곡 대상 자동 수집
   - 186곡(제목 완전 일치) + 2곡(fuzzy: #255, #263) = **188곡 확보**
   - 실패 원인: 검색결과없음 58, 악보·유튜브 링크만 있음 44, 매칭 실패 12

2. **`/crawl-lyrics` 스킬 구조 재편**
   - 사이트별 전략을 `.claude/skills/crawl-lyrics/sources/*.md`로 분리 (`maria.md`, `yseng.md`, `pdf.md`, `_template.md`)
   - 실행 시 "어떤 소스를 어떤 우선순위로 쓸지 사용자에게 확인 후 진행" 흐름 명시
   - 신규 크롤러: `scripts/crawler/crawl_yseng.py` (제목 완전 일치 + `--fuzzy` 근사 매칭 + resume)

3. **단일 진리 저장소 원칙 확립**
   - `scripts/build_songs_json.py` **제거** — 매번 덮어쓰기 구조는 `사용자수정시각`·PDF 추출·`신뢰도` 같은 파생값을 날릴 위험
   - `scripts/crawler/_merge.py` 신설 — 공용 in-place 병합 헬퍼
     - `사용자수정시각` 있으면 skip (사용자 수작업 보호)
     - 소스 우선순위 **maria(3) > yseng(2) > PDF(1)** — 높은 우선순위만 덮어쓰기 허용
     - 본문이 바뀌면 파생 필드(`가사.절별`/`가사.절구조`/`신뢰도`) 자동 리셋
   - 각 크롤러가 `--no-merge`, `--merge-only`, `--force` 공통 플래그 지원

4. **`/fix-lyrics-format` 분리**
   - 기존 스킬이 "본문 정리"와 "절 구성"을 함께 해 책임이 섞여 있던 문제
   - **`/clean-lyrics` 신설** — 본문 정리만 수행 (X2 슬래시, X3 오염, X4 빈 줄, X7 영문 잔존, X8 짧은 절, X11 악보 메타)
   - `/fix-lyrics-format`는 `status: deprecated` 표시 — 호환성 유지
   - 공용 유틸을 `scripts/_lyrics_cleanup.py`로 이관해 중복 코드 제거

5. **`/clean-lyrics` 정교화**
   - **X11(악보 메타) 신규 규칙** — 음표(♩♪), 템포(=숫자), 박자(4/4), 단독 조표(G/F#), BOM·제로폭 문자 제거. `remove_slashes` 이전에 실행해 박자 패턴 보존.
   - **X7(영문 잔존) 마커 독립 리팩토링** — 마커 없는 줄도 처리하도록 확장. 대신 영문 원제(Oh Father, Kumbaya 등)가 지워질 위험이 있어 **opt-in** 정책 도입 + 인터랙티브 프롬프트에서 동작·부작용·적용 기준 상세 설명.
   - 전체 495곡에 적용 — **177곡 교정** (X4: 107건, X3: 99건, X2: 67건)

## 후속 과제 (S-003 재개 시 고려)

- **`/structure-lyrics` 구현** — 현재 DRAFT. 188곡의 `가사.절별`/`가사.절구조`가 `null`로 초기화된 상태라, 절/후렴 재추론이 막혀 있음. S-003 완료 기준 도달의 최대 병목.
- **영어곡 2곡 처리** — #448 Beautiful, #460 God will make a way. 수작업 입력 경로 필요.
- **형식 통과율 재검증** — yseng 본문이 대거 교체됐고 파생 필드가 리셋된 상태. `/validate-lyrics-format`으로 현재 통과율 재측정 필요.
- **`4 4` 류 과거 잔재** — `4/4`가 `4 4`로 쪼개져 남은 몇 곡(#32, #200 등). 현상 유지. `/structure-lyrics`의 블록 경계 판정으로 자연 흡수 기대.

## 회고

**잘된 점**
- 사이트별 전략 분리(`sources/*.md`)로 새 소스 편입 비용이 크게 내려감. 앞으로 추가 소스를 쉽게 붙일 수 있는 구조가 생김.
- 공용 유틸(`_merge.py`, `_lyrics_cleanup.py`) 도입으로 크롤러·스킬 간 정책이 하나로 수렴.
- 고신뢰 커버리지가 단일 세션에서 35% → 73%로 오름. 가장 큰 PDF 잔재 한 덩어리가 제거됨.
- 병합 정책(우선순위 + 사용자 수정 보호)이 실제 병합 실행 시 예상대로 동작함을 검증(사용자수정 17곡 / maria 172곡 모두 영향 없음).

**아쉬운 점**
- `remove_slashes`와 `strip_music_notation`의 순서 이슈로 이미 `4/4` → `4 4`로 쪼개진 곡은 이번 라운드에서 회수하지 못함. 설계 초기에 둘의 의존 순서를 문서화했다면 피할 수 있었음.
- `/structure-lyrics`가 미구현인 상태에서 188곡의 파생 필드를 대거 리셋한 결과, 선곡 추천에서 구조가 필요한 질의가 당장은 약해짐. 구현 우선순위가 올라감.

**다음에 바꿀 것**
- 크롤러·정리 스킬 설계 시 "함수 실행 순서와 상호 의존" 표를 각 모듈 최상단에 명시.
- `/clean-lyrics`에 제거 결과 미리보기 모드(`--dry-run`)를 추가해 일괄 실행 전에 영향 범위를 확인할 수 있도록.
