# S-005: 웹 어시스턴트 + 편집기 통합 서버

**상태:** 완료
**기간:** 2026-04-24 (단일 세션)
**완료 기준 달성률:** 100% (end-to-end Claude 호출 실제 과금 테스트는 사용자가 별도 수행)

## 목표

1. 지인(소수)들이 브라우저에서 이 프로젝트의 스킬을 프롬프팅으로 호출할 수 있는 웹 인터페이스 구축
2. 기존 가사 편집기([viewer/](../../../viewer/))도 같은 서버 도메인에 통합
3. ngrok으로 외부 공유 가능, 인증은 URL 공유로만 통제

## 배경

- 기존에 스킬 실행은 Claude Code CLI를 아는 사용자만 가능 → 선곡 담당자가 다른 성가대원에게 편집/선곡 작업을 위임하기 어려움
- 가사 편집기는 [viewer/server.py](../../../viewer/server.py) 별도 프로세스로만 사용자 접근 가능 → 포트·URL 분리로 공유 번거로움

## 아키텍처

```
브라우저 ─SSE─> FastAPI (:8000) ─> Claude Agent SDK ─> Anthropic API
                   │
                   ├ cwd = s:/song_recommendation (스킬 자동 로드)
                   ├ allowed_tools = Read/Write/Edit/Glob/Grep/WebFetch/Bash
                   ├ permission_mode = acceptEdits
                   ├ asyncio.Lock (세션 1개)
                   └ Write/Edit 경로 s:/song_recommendation/ 외부 차단

viewer/ ─ StaticFiles 마운트(/editor/) ─> 기존 가사 편집기
data/songs.json ─ GET/PUT /api/songs ─> 편집기용 읽기/쓰기 (SONGS_LOCK)
```

## 알려진 한계 / 후속 과제

- **end-to-end Claude 응답**: 사용자가 실제 `ANTHROPIC_API_KEY`로 첫 프롬프트를 돌려 과금·결과를 직접 확인해야 함 (이번 세션 중 과금 회피 목적 미수행)
- **편집기 ↔ Claude 경합**: 같은 `songs.json`을 둘 다 쓸 수 있음. `SONGS_LOCK`은 편집기끼리만 직렬화. Claude vs 편집기는 마지막 쓰기 승. 운영 시 "가사 건드리는 스킬 실행 중 편집기 저장 자제" 로 회피
- **인증 부재**: ngrok URL이 유일한 게이트. 사용자는 콘솔에서 월 spend limit 설정 필수
- **미처리된 원 요청**: 세션 초반의 "2026년 5월 성가표" 선곡 작업은 인프라 구축으로 선회하며 보류. 이제 이 서버 위에서 `/recommend-hymns` 프롬프트로 재개 가능

## 회고

### 배운 점
- Claude Agent SDK는 `cwd` 만 맞추면 `.claude/skills/` 를 자동 로드 → 스킬 노출을 위해 별도 등록이 불필요
- SSE + FastAPI `StreamingResponse` 조합이 WebSocket보다 훨씬 간단 (단방향이면 충분)
- Windows에서 `run_in_background`로 띄운 프로세스는 TaskStop해도 자식 python이 leak — 운영 시 `Stop-Process`로 직접 종료 필요
- PowerShell `$env:(동적이름)` 문법은 불가 → `Set-Item Env:$name` 패턴이 정답
