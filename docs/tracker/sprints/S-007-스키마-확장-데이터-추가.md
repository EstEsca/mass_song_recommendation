# S-007: 곡 스키마 확장 및 데이터 추가 정리

**상태:** 활성
**기간 시작:** 2026-04-25
**기간 종료:** —

## 목표

1. 현재 schema v2.0이 포괄하지 못하는 **곡 부가 정보**(조표 등)를 식별하고, 스키마에 반영한다.
2. 추가된 필드에 대해 **실제 데이터를 채우는 경로**(소스, 입력 도구, 검증)를 확립한다.
3. 파생물(`songs.json`·`songs_index.json`) 및 스킬/뷰어가 새 필드를 안전하게 소비하도록 연결한다.

대표 작업: **조표(key signature) 데이터 추가**.

## 배경

- schema v2.0(2026-04-25 채택, ADR-006)은 색인·가사 중심으로 재정의됐지만, 곡 자체의 **음악적 메타데이터**(조표·박자·빠르기 등)는 포함되지 않음.
- 선곡 실무에서 조표 정보가 필요한 장면이 반복 등장 — 예: 반주자와의 조율, 조 이동 결정, 인접 곡 간 조성 흐름 고려.
- SSoT 편집 파일이 `data/source/곡정보.xlsx` 단일 파일로 정리된 직후이므로, 필드 추가 비용이 상대적으로 낮은 타이밍.

## 범위

### 스키마 설계
- [ ] 추가할 필드 목록 확정 (조표는 확정, 그 외는 사용자와 협의)
  - 후보: 조표, 박자, 빠르기, 음역, 작사자 분리 등
- [ ] 필드별 값 형식/vocab 규칙 정의 (예: 조표 표기 컨벤션 — `"G"`, `"e단조"`, `"F#"` 중 무엇을 쓸지)
- [ ] ADR 작성 (`docs/spec/decisions/ADR-007-schema-v2.x-확장.md` 또는 유사)
- [ ] `docs/spec/schema.md` 갱신 + `metadata.schema_version` 범프

### 데이터 소스·입력 경로
- [ ] 조표 데이터 소스 탐색 (청소년청년성가집 PDF 악보 첫 마디 조표, maria·yseng의 악보 이미지, 기존 파생 텍스트에서 추출 가능성)
- [ ] 자동 추출 가능성 확인 → 가능한 범위는 자동, 나머지는 수작업 경로 마련
- [ ] `data/source/곡정보.xlsx`에 `조표` 컬럼(또는 필요한 컬럼) 추가

### 파생물 · 스킬 · 뷰 연동
- [ ] `build_songs_json.py`가 새 필드를 반영하도록 갱신
- [ ] `build_song_index.py`가 경량 색인에 포함할지 결정
- [ ] 뷰어(`server/`)에서 새 필드 표시
- [ ] `/recommend-hymns`·기타 스킬이 필요 시 활용할 수 있도록 스키마 문서 반영

## 완료 기준

| 기준 | 목표 |
|------|------|
| 스키마 버전 업데이트 | v2.1 (또는 확정 버전)로 반영 |
| 조표 필드 커버리지 | ≥ 80% (자동 추출 가능 범위) |
| ADR 작성 | 스키마 확장 근거 문서화 |
| 뷰어 반영 | 조표가 곡 상세에서 보이도록 |
| 검증 | `songs.json` 빌드 후 `schema_version` 일치·타입 체크 통과 |

## 포함 이슈

- (신규) 스키마 v2.x 확장 — 조표 등 음악적 메타 추가
- (신규) 조표 데이터 수집·입력
- 기존 이슈 중 "곡 비고란 데이터 입력"(#5) 등과 충돌/병합 여부 검토
