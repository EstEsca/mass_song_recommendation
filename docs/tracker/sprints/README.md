# 스프린트 정책

**스프린트(Sprint)**: 작은 목표를 중심으로 여러 이슈를 묶어 해결하는 작업 단위.

> **작업 관리 정책**: 스프린트는 [작업 관리 정책](../work_management.md)의 한 단위다.
> 구체적 작업은 [이슈](../../../ISSUES.md), 미래 검토 아이디어는 [고려사항](../CONSIDERATIONS.md)에서 관리.

## 구조

```
docs/tracker/sprints/
├── README.md                   # 이 문서 (정책)
├── CURRENT.md                  # 현재 활성 스프린트 포인터 (심볼링크 대신)
├── S-001-기반-구축.md          # 완료된 스프린트 (시간순)
├── S-002-가사-파이프라인.md
└── ...
```

## 스프린트 구성 요소

| 필드 | 내용 |
|------|------|
| **ID** | `S-NNN` (순번, 3자리) |
| **제목** | 스프린트 핵심 목표를 한 줄로 |
| **목표** | 달성하고자 하는 것 (1~3 항목) |
| **상태** | `활성` / `보류` / `완료` / `중단` |
| **기간** | 시작일 / 종료일 |
| **포함 이슈** | ISSUES.md 번호 목록 |
| **완료 기준** | 측정 가능한 지표 (곡 수, 통과율 등) |
| **진행 로그** | 주요 마일스톤 시간순 기록 |
| **회고** | 완료 후 배운 점/다음 스프린트 제안 |

## 라이프사이클

1. **생성**: 목표 정의 → `S-NNN-제목.md` 작성, 상태 `활성`
2. **진행**: 이슈 완료 시 스프린트 로그에 추가
3. **보류**: 다른 스프린트로 컨텍스트 전환 시 상태 `보류` (나중에 재개 가능)
4. **완료**: 완료 기준 충족 시 상태 `완료` + 회고 작성
5. **중단**: 포기 시 상태 `중단` + 사유 기록

## 배타적 활성 규칙

- **활성 스프린트는 최대 1개**. 새 스프린트를 활성화하면 기존 활성 스프린트는 자동으로 `보류` 상태로 전환.
- `보류`는 미완료지만 현재 작업 대상이 아님을 의미. 언제든 재활성 가능.

## 현재 스프린트 확인

- `docs/tracker/sprints/CURRENT.md` → 현재 활성 스프린트 파일 경로
- 활성 스프린트가 없으면 `CURRENT.md`에 "없음" 표시
- 세션 재개 시 `CURRENT.md`를 먼저 읽으면 현재 작업 맥락을 즉시 파악 가능

## 이슈와의 관계

- **이슈**: 단일 작업 단위 (ISSUES.md)
- **스프린트**: 여러 이슈를 묶은 목표 단위

이슈는 여러 스프린트에 걸쳐 있을 수 없다. 스프린트 경계가 이슈 경계보다 우선.

## 체크리스트와의 관계

각 스프린트는 **본문(이 디렉토리)** + **체크리스트(`docs/tracker/sprints_checklist/`)** 한 쌍으로 운영된다.

- **본문**: 목표·범위·완료 기준·회고 (의도와 결과의 기록)
- **체크리스트**: 단계별 행동 점검표 (Claude·사용자·공동 책임 표시)

새 스프린트 생성 시 **본문과 체크리스트를 같이 작성**한다. 체크리스트 정책: [../sprints_checklist/README.md](../sprints_checklist/README.md), 템플릿: [../sprints_checklist/_TEMPLATE.md](../sprints_checklist/_TEMPLATE.md).
