## 목표

1. 외부에서 이미 작성된 선곡표(다른 본당 주보, 별도로 만든 시트 등)를 텍스트·이미지로 받아 우리 운영 로그(`data/source/선곡표.xlsx`)에 통합 import.
2. 변환 후 `/log-setlist`(S-011 산출물)의 `POST /api/setlist`로 행 append하는 흐름을 자동화.

대표 작업: 외부 양식의 한 달치 선곡표를 한 번에 우리 7컬럼 Tall 로그로 옮겨 담기.

## 배경

- 이슈 #4의 또 다른 재정의 (2026-04-30 기준).

## 범위 — 3단계 흐름

### Step 1. 입력 + 플랜 확인

**입력 형태**
- (a) 텍스트 파일: 사용자가 미리 만든 `.txt` 또는 마크다운 표
- (b) 이미지 붙여넣기: 사용자가 스크린샷·사진을 채팅에 첨부 → Claude 비전으로 구조 분석

**플랜 단계**
- LLM이 입력을 분석해 다음을 사용자에게 제시:
  - 컬럼 수 / 행 수 / 헤더 / 머지 셀
  - 데이터 영역과 정적 영역 구분
  - 추천 결과의 어느 필드가 어느 셀에 매핑될지 가설
- 사용자가 매핑을 확인·수정. 모호하면 되묻기.

### Step 2. LLM 변환 → 엑셀 호환 양식

**출력 형식 후보**
- **TSV**: 가장 단순. 엑셀에 Ctrl+V로 즉시 셀 분리. 머지·서식 없음.
- **xlsx 직접 생성**: openpyxl로 셀별 값·서식·머지 반영. 인쇄용에 가까움.
- **마크다운 표**: 채팅·문서 친화적이나 엑셀 호환은 약함.

기본은 **TSV** + 필요 시 xlsx 옵션. 머지/서식 보존이 필수면 xlsx로.

**매핑 규칙 표현법** (미해결 — 첫 세션에서 결정)
- 단순 dict: `{"row 2 col B": "{번호}", "row 2 col C": "{제목}"}`
- 또는 양식 자체에 placeholder: `"{번호}\t{제목}\t{선정이유}"` 식 템플릿 문자열

### Step 3. 에셋화

**저장 구조 안**
```
data/source/output_templates/
├── README.md                       # 템플릿 사용법 + 인덱스
├── <name>.json                     # 메타 (컬럼 수·헤더·매핑 규칙)
├── <name>.tsv                      # 빈 양식 예시 (placeholder 포함)
└── <name>.xlsx (옵션)              # 머지·서식 필요 시
```

**메타 JSON 스키마(안)**
```jsonc
{
  "name": "본당-주보-A",
  "created": "2026-MM-DD",
  "columns": ["주일", "전례명", "봉헌", "성체", "파견", "묵상"],
  "row_per_song": false,             // 또는 true
  "mapping": {
    "{주일}": "meta.date",
    "{전례명}": "meta.name",
    "{봉헌}": "results.봉헌[0].번호 + ' ' + results.봉헌[0].제목",
    ...
  },
  "format": "tsv",                   // tsv | xlsx
  "preview": "본당-주보-A.tsv"
}
```

이후 `/recommend-hymns` 결과 + `<template>` → `scripts/render_output.py`로 양식화된 출력 즉시 생성.

## 완료 기준

| 기준 | 목표 |
|------|------|
| 텍스트 입력 → 양식 추출 | 표 형태(헤더+행) 입력 시 매핑 규칙 자동 제안 |
| 이미지 입력 → 양식 추출 | 단순 인쇄 양식 1~2개로 동작 검증 |
| TSV 출력 | 엑셀에 Ctrl+V로 정확히 셀 분리 |
| 에셋 저장·재사용 | 같은 템플릿에 다른 추천 결과를 매핑 가능 |
| recommend-hymns 결과 매핑 | 4주일치 추천을 1초 안에 양식화 |

## 미해결 질문 (첫 세션에서 결정)

1. **매핑 규칙 표현법** — placeholder 치환 vs JSONPath 식 vs Python 식
2. **이미지 비전 정확도** — Claude의 비전이 표 구조를 얼마나 정확히 추출하는가? 첫 세션에서 사용자 실제 양식 1~2장으로 테스트
3. **다중 행 처리** — 한 곡 = 한 행 vs 한 양식 = 여러 곡 (주보 양식)
4. **xlsx 출력 필요성** — TSV로 충분한가, 머지·서식이 자주 필요한가?
5. **스킬 이름** — `/format-output`, `/render-output`, `/apply-template` 중 무엇?
