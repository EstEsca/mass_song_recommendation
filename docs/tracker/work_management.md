# 작업 관리 정책 (이슈 · 고려사항 · 스프린트)

이 프로젝트의 작업은 **세 단위**로 관리된다. 셋은 서로 독립되어 있지만 **유기적으로 참조**된다.

## 세 가지 작업 단위

| 단위 | 위치 | 크기 | 의도 |
|---|---|---|---|
| **이슈** (Issue) | [ISSUES.md](../../ISSUES.md) | 작음 (1~3시간) | 구체적 작업 항목 |
| **고려사항** (Consideration) | [CONSIDERATIONS.md](CONSIDERATIONS.md) | 미정 | 고민해볼만한 아이디어·도입 검토 |
| **스프린트** (Sprint) | [sprints/](sprints/) | 큼 (며칠~주) | 여러 이슈를 묶은 목표 단위 |

## 관계

```
   ┌─ 스프린트 S-NNN (현재 작업의 큰 맥락) ──────────────┐
   │   목표: ...                                          │
   │   ├─ 포함 이슈:        #29, #30, #31 ...             │
   │   └─ 관련 고려사항:    C-05, C-07 (참조만)           │
   └──────────────────────────────────────────────────────┘
                        ▲
                        │ (사용자/Claude가 새 작업 발견)
                        │
   ┌────────────────────┴────────────────────┐
   │                                          │
이슈 #NN (구체 작업)                  고려사항 C-NN (아이디어)
   │                                          │
   └─ 어느 스프린트에 속하지 않을 수도 있음 ──┘
      (단발성 작업·미래 검토 항목)
```

## 항목 추가 가이드

### 이슈 추가
- **언제**: 1~3시간 이내에 끝낼 수 있는 구체적 작업
- **어떻게**: ISSUES.md 마지막 행에 `| #NN | 시작 전 | 담당자 | 제목 | 설명 | 등록일 |`
- **누가**: Claude(`/add-issue` 스킬) 또는 사용자(직접 편집)
- **스프린트 인용**: 설명에 `(S-NNN 일부)` 또는 `(S-NNN에 흡수)` 표기 가능

### 고려사항 추가
- **언제**: 지금 결정하지 못하는 아이디어, 도입 검토가 필요한 항목, 막연한 고민
- **어떻게**: CONSIDERATIONS.md 끝에 `## C-NN: 제목` 섹션 추가. 표준 구조: 상태·카테고리·문제·검토 포인트·도입 시 이점·도입 시 비용.
- **누가**: Claude(스킬) 또는 사용자(직접 편집)
- **스프린트·이슈 인용**: 본문에 `S-NNN`, `#NN` 자연스럽게 표기

### 스프린트 추가
- **언제**: 여러 이슈가 한 목표를 향하거나, 큰 맥락의 작업이 시작될 때
- **어떻게**: 본문(`docs/tracker/sprints/S-NNN-*.md`) + 체크리스트(`docs/tracker/sprints_checklist/S-NNN-*.md`) 동시 작성
- **포함 이슈** 섹션에 `#NN` 목록
- **관련 고려사항** 섹션(있으면)에 `C-NN` 목록
- 정책: [sprints/README.md](sprints/README.md), 체크리스트 정책: [sprints_checklist/README.md](sprints_checklist/README.md)

## 상호 참조 컨벤션

- **이슈 ID**: `#NN` (예: `#36`)
- **고려사항 ID**: `C-NN` (예: `C-05`)
- **스프린트 ID**: `S-NNN` (예: `S-008`)

문서 간 인용은 자연스러운 문장 안에 ID를 끼워넣는다:
- "이슈 #36으로 구현 중"
- "C-05 임베딩과 관련"
- "S-008에 흡수됨"

링크가 필요하면 마크다운 링크: `[#36](../../ISSUES.md)`, `[C-05](CONSIDERATIONS.md)`, `[S-008](sprints/S-008-스키마-v2.0-마이그레이션.md)`.

## 라이프사이클 흐름 (전형적 패턴)

```
1. 사용자/Claude가 작업·아이디어 발견
       │
       ├─ 작은 작업이면 → 이슈 등록
       │
       └─ 막연한 고민이면 → 고려사항 등록

2. 여러 이슈가 한 목표로 모임 → 스프린트 신설
   - 본문 + 체크리스트 동시 작성
   - 포함 이슈에 기존 #NN 모음
   - 관련 고려사항(C-NN)을 "참조"로 표시

3. 스프린트 진행 중
   - 새 작업 발견 → 새 이슈 #NN 등록 + 스프린트 본문에 추가
   - 보류 아이디어 발견 → 새 고려사항 C-NN 등록
   - 결정 필요한 도입 → 고려사항에서 검토 후 이슈로 승격

4. 스프린트 완료
   - 회고 작성 (잘된 점·교훈·다음 스프린트 후보)
   - 포함 이슈 → 완료 마킹
   - 흡수·해결된 기존 이슈 → 완료 마킹
   - 무의미해진 기존 이슈 → 스킵
   - 회고에서 도출된 새 고려사항 등록 (필요 시)
```

## 역방향 작업 (사용자 직접 추가)

사용자는 스프린트와 무관하게 직접 추가할 수 있다:

- **이슈에 직접**: 작은 단발성 작업(예: "비고란 텍스트 정정", "특정 곡 가사 수정")은 스프린트 없이 이슈로만 등록 가능. 등록 후 시간 날 때 처리.
- **고려사항에 직접**: 미래 검토할 아이디어(예: "성가 추천에 분위기 슬라이더 도입")는 스프린트 만들기 전 고려사항으로 적어둠. 검토 후 도입 결정되면 이슈·스프린트로 승격.

이 흐름은 **소규모 작업과 장기 아이디어가 스프린트 외부에서도 누적**되도록 보장한다.

## 검토 시점

| 시점 | 점검 대상 |
|------|----------|
| 새 세션 시작 | `sprints/CURRENT.md` → 활성 스프린트 본문 → 활성 스프린트 체크리스트 → 관련 이슈·고려사항 |
| 단계 완료 | 체크리스트 항목 마킹 + 이슈 상태 갱신 |
| 스프린트 완료 | 회고 + ISSUES.md 정리 + CURRENT.md 갱신 |
| 분기 또는 3개월마다 | CONSIDERATIONS.md 재검토 (도입/폐기/스프린트 승격) |

## git 운영 규약 (요약)

여러 머신을 번갈아 쓰므로 작업 단위와 별개로 git 규약을 따른다. 상세는 [manuals/multi_machine.md](../manuals/multi_machine.md).

- **세션 시작**: `git pull` 선행. **세션 종료**: 커밋 + `git push` 후 종료.
- **브랜치**: 로컬은 `master` 직접, 큰 패치는 `feat/<주제>` → master, 클라우드 세션은 `claude/<주제>` → 사용자가 로컬 병합.
- **커밋 메시지**: Conventional Commits — `type(scope): 한국어 요약`. type은 `feat`·`fix`·`docs`·`data`·`refactor`·`chore`, scope는 `S-NNN` 또는 영역.
- **데이터**: `data/` 전부 커밋 대상. xlsx를 바꿨으면 `rebuild.py` 후 파생 JSON과 함께 커밋.

## 자주 묻는 질문

**Q. 이슈는 반드시 어느 스프린트에 속해야 하나?**
A. 아니다. 단발성 작업은 스프린트 없이 이슈로만 존재할 수 있다. 단, 큰 맥락이 모이면 스프린트로 묶어 추적성을 높이는 것이 권장된다.

**Q. 고려사항이 이슈로 승격되는 조건은?**
A. 도입을 결정했고, 1~3시간 단위로 쪼갤 수 있을 때. 결정 자체가 어려우면 고려사항에 머무른다.

**Q. 스프린트 도중에 고려사항이 새로 생길 수 있나?**
A. 가능. 진행 중 발견한 보류 아이디어는 즉시 CONSIDERATIONS.md에 등록하고, 스프린트 본문 "관련 고려사항"에도 한 줄 추가.

**Q. 고려사항은 영원히 살아있는가?**
A. 분기/3개월 단위 재검토에서 도입·폐기·승격 결정. 폐기는 git 히스토리에 남지만 본문에서는 제거.
