# 스프린트 체크리스트 정책

각 스프린트마다 **Claude와 사용자가 단계별로 점검해야 할 항목**을 명시한 체크리스트 문서를 둔다. 스프린트 본문(`docs/tracker/sprints/S-NNN-*.md`)이 *목표·범위·회고*를 다룬다면, 체크리스트(`docs/tracker/sprints_checklist/S-NNN-*.md`)는 *행동 점검표*에 해당한다.

## 구조

```
docs/tracker/sprints_checklist/
├── README.md                        # 이 문서 (정책)
├── _TEMPLATE.md                     # 새 스프린트 시작 시 복사할 템플릿
├── S-007-스키마-확장-데이터-추가.md
├── S-009-출력-표-양식-도구.md
└── ...
```

- **파일명 = 스프린트 본문과 동일.** 1:1 대응되어야 양쪽 추적이 쉽다.
- **정책상 모든 활성·보류 스프린트는 체크리스트가 있어야 한다.** 완료 스프린트는 사후 추가하지 않아도 무방하지만, 회고에서 학습할 가치가 있으면 회고용으로 보존 가능.

## 체크리스트 구성

| 섹션 | 점검 시점 | 책임 |
|------|----------|------|
| **시작 전** | 스프린트 활성화 직전 | 주로 사용자 (입력·승인) |
| **진행 중** | 각 단계 진입·종료 시 | 주로 Claude (산출물·검증) |
| **완료 전** | 스프린트 완료 기준 충족 시 | 공동 |
| **완료 후** | 스프린트 종료 직후 | Claude (회고·문서·이슈 갱신) |

각 항목 앞에 책임 표시:

- `[👤]` — 사용자 단독 책임 (입력·결정·검수)
- `[🤖]` — Claude 단독 책임 (구현·문서·검증)
- `[🤝]` — 공동 책임 (협의·합의)

체크박스 `[ ]` → `[x]`로 진행도 표시. 미해결 사유는 항목 옆에 메모.

## 라이프사이클

1. **생성**: 새 스프린트 본문 작성과 함께 체크리스트도 작성. `_TEMPLATE.md` 복사 후 스프린트 맞춤화.
2. **활성화**: `CURRENT.md` 갱신 시 체크리스트 경로도 함께 표시.
3. **세션 시작 시**: Claude는 활성 스프린트의 체크리스트를 먼저 읽고 진행도를 파악.
4. **항목 완료 시**: 체크리스트의 `[ ]` → `[x]`로 마킹 + 필요 시 메모 추가.
5. **스프린트 완료 시**: 모든 필수 항목이 체크되어야 완료 처리. 미체크 항목은 회고에 사유 기록.

## 정책

- **누가 검토하는지가 명확해야 한다** — 책임 표시(👤/🤖/🤝)는 필수.
- **검증 가능해야 한다** — "잘 작동하는지 본다" 같은 모호함 금지. "스크립트 dry-run 통과" "곡 N개 처리 확인" 등 측정 가능한 표현.
- **블로킹과 비블로킹 구분** — 일부 항목은 진행에 필수(블로킹), 일부는 권장사항. 필수에는 `(블로킹)` 표시.
- **체크리스트 자체도 살아있다** — 진행 중 새 점검 항목이 발견되면 추가. git에서 변경 이력 추적.
