# 매뉴얼 정책

**매뉴얼(Manual)**: 사용자가 따라할 수 있는 **영구적 절차 가이드**.

스프린트와 달리 일회성이 아니고, ADR과 달리 결정 근거가 아닌 *절차*를, SKILL.md와 달리 Claude 동작이 아닌 *사람의 행동*을 다룬다.

## 다른 문서와의 관계

| 문서 | 다루는 것 | 시점성 |
|---|---|---|
| **매뉴얼** (이 폴더) | 사람이 따라하는 절차 | 영속적, 반복 사용 |
| **SKILL.md** (`.claude/skills/`) | Claude 동작 정의 | 영속적 |
| **ADR** (`docs/spec/decisions/`) | 결정의 근거 (왜) | 영속적 |
| **스프린트** (`docs/tracker/sprints/`) | 일회성 목표·진행도 | 시한적 |
| **이슈** (`ISSUES.md`) | 작은 작업 단위 | 시한적 |

|---|---|---|

## 작성 규칙

1. **명명**: `<주제>.md`. 영어 snake_case 권장(예: `server_runtime.md`, `migration_v1_to_v2.md`). 한글이 더 자연스러우면 한글도 허용.
2. **구성** (권장):
   - **목적**: 매뉴얼이 다루는 시나리오
   - **사전 준비**: 의존성·환경 변수·계정 등
   - **절차**: 단계별 명령어/UI 클릭. 복사해 쓸 수 있게 코드블록.
   - **검증**: 정상 동작 확인 방법
   - **트러블슈팅**: 자주 발생하는 오류와 해결책
   - **관련 문서**: SKILL.md / ADR / 스프린트 cross-link
3. **코드블록 언어**: `bash` / `powershell` / `jsonc` 명시. 사용자 OS(Windows)와 호환되는 명령 우선.
4. **버전 표기**: 절차가 특정 버전(스키마 v2.0 등)에 의존하면 상단에 명시.
5. **갱신 트리거**: 관련 코드/스킬이 변경되면 매뉴얼도 갱신. 매뉴얼 상단에 갱신일 기록.

## 매뉴얼 추가 흐름

1. **사용자가 요청**: "X에 대한 매뉴얼 만들어줘" / "Y 절차 정리해줘"
2. **Claude가 작성**: 위 구성을 따라 새 파일 생성. 인덱스에 한 줄 추가.
3. **사용자 검수**: 실제 절차로 따라가며 빠진 단계·오류 보고
4. **반영**: 피드백 반영 후 확정

## 폐기·이전

- 절차가 무의미해지면 매뉴얼 본문 상단에 **DEPRECATED** 표시 + 사유 + 대체 매뉴얼 링크. 본문은 한동안 보존(과거 절차 참고용).
- 완전히 무관해지면 git 히스토리만 남기고 파일 삭제.
