# Songs Viewer

`data/songs.json`을 탐색/검토/편집하기 위한 단일 페이지 웹앱. 선곡 담당자가 가사 품질을 검수하고 수정하는 UI.

## 실행

### 편집 모드 (권장)

로컬 백엔드를 띄우면 가사 편집이 `data/songs.json`에 바로 저장됩니다.

```bash
# 프로젝트 루트에서
python viewer/server.py

# 또는 임의 포트
python viewer/server.py 9000
```

기본 포트는 `8765`. 브라우저에서 접속:

```
http://127.0.0.1:8765/
```

- 의존성 없음 (Python 표준 라이브러리만 사용)
- 서버는 `127.0.0.1`에만 바인딩 — 외부에서 접근 불가
- 종료: 터미널에서 `Ctrl+C`

### 읽기 전용 모드

백엔드 없이 파일을 직접 열어도 **보기**는 가능합니다 (편집 불가):

```
file:///.../viewer/index.html
```

에디터에 `readonly` 속성이 붙고 저장 버튼이 작동하지 않습니다.

## 주요 기능

- **좌측**: 통계 → 필터 → 곡 목록 테이블 (스크롤)
- **우측**: 선택한 곡의 상세 + 가사 에디터 + 실시간 프리뷰
- 곡을 선택하면 에디터가 자동 활성 — 별도 "편집 버튼" 없음
- 편집 중 `●` dirty 마커가 깜빡임 → 변경사항 있음을 표시
- 가사 수정이 저장된 곡은 신뢰도 배지 옆 `*` — "신뢰도 재평가 필요"

## 저장 시맨틱

| 상황 | 동작 |
|---|---|
| 다른 곡으로 이동 (클릭 / j / k / ◀ ▶) | 변경이 있으면 **자동 저장 후 이동** |
| 자동 저장 실패 | **이동 차단**, 에러 메시지 표시 |
| 본문을 전부 지운 상태에서 이동 | **이동 차단** (Ctrl+S로만 명시적 저장 가능) |
| `Ctrl+S` | 명시적 저장 (빈 본문도 허용) |
| `Esc` | 현재 편집 **되돌리기** (마지막 저장 상태로 복원) |
| 탭 닫기 시 dirty 상태 | 브라우저 확인 대화상자 |

## 단축키

| 키 | 동작 |
|---|---|
| `j` | 다음 곡 (현재 필터 기준) |
| `k` | 이전 곡 |
| `Ctrl+S` / `Cmd+S` | 현재 곡 명시적 저장 |
| `Esc` | 변경사항 되돌리기 |

`j`/`k`는 입력 요소에 포커스가 있으면 무시됩니다 (검색창 등에서 방해 안 됨).

## API

에디터가 호출하는 엔드포인트:

| Method | Path | 설명 |
|---|---|---|
| `GET` | `/api/songs` | `songs.json` 전체 반환 |
| `PUT` | `/api/songs/<번호>` | 해당 곡의 가사 필드 패치 |

`PUT` 요청 본문 예:

```json
{ "가사": { "본문": "[1절]\n..." } }
```

허용 필드: `본문`, `절별`, `절구조`, `참조URL`. 저장 시 서버가 `사용자수정시각`을 ISO 타임스탬프로 자동 기록.

응답 예:

```json
{ "ok": true, "사용자수정시각": "2026-04-22T10:30:15", "changed": ["가사.본문"] }
```

## 안전망: git

`data/songs.json`은 git에 커밋되어 있습니다. 잘못 저장했을 때:

```bash
# 최근 커밋 상태로 롤백
git checkout HEAD -- data/songs.json

# 특정 커밋으로 롤백
git log -- data/songs.json           # 이력 확인
git checkout <커밋해시> -- data/songs.json
```

**권장 루틴**: 편집 세션이 끝날 때마다 커밋.

```bash
git add data/songs.json
git commit -m "edit: N곡 가사 수정"
```

## 문제 해결

- **"songs.json 로드 실패"**: 백엔드가 안 떠있는데 `http://` 경로로 접속했을 때. `python viewer/server.py`를 먼저 실행하거나, `file://`로 index.html을 직접 열기.
- **저장 실패로 이동 차단**: 메시지를 읽고 조치. 보통 네트워크(서버 꺼짐) 또는 디스크 쓰기 실패.
- **빈 본문으로 저장하고 싶음**: autosave는 거부하지만 `Ctrl+S`는 허용. 의도적 지움 시 Ctrl+S를 누르고 이동.
